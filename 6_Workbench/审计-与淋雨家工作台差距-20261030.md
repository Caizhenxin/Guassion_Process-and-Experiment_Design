## §1 跨对话窗口协作：为什么是 0

**证据（A 侧）**：对 `lib/client.js`、`dsh/*.js`、`README.md` 全量 grep `跨会话|派单|唤醒|通知场景|回执|wake|inbox` → **0 命中**。插件只会用 `ctx.connection`（注册 HTTP 路由）和 `node:fs`，没有「把消息投给另一条会话」的能力。

**B 的做法**（摘自 `05-协作与规矩/一-全局铁律.md` L58-59、L78-87）：
- 派单 ≠ 公告：要对方**动手**才叫派单，必须 `通知场景.mjs --to <面板> --wake`，判据是回显 `✓ …（HTTP 200 accepted=true）`，只落盘 = 没叫醒；
- 回执必须走工具投递：只在自己窗口说「我做完了」**不算交付**（发起方收不到 = 没闭环）；
- 硬上限：一件事 ≤3 条消息（派单 + 回执 + 收尾），收到知悉**一个字都不许回**（防 AI 互相客套烧 token）；
- 台账：`待回执.mjs --me <面板>`、`读会话尾巴.mjs` 兜底。

**结论**：这不只是「没写代码」，是**能力缺口**——我这条插件没有跨会话投递接口。三条路，按代价排：

1. **(c) 先做文件层（今天就能有）**：看板加「待认领 / 待回执」两栏；交接 §〇 里写清「在等谁回」；每轮开场读一次。收到回执后删行。→ 能保证**不丢**，但**不实时**。
2. **(a) 验证引擎接口（30 分钟，关键未知项）**：DSH Desktop 是否提供跨会话投递（本地 HTTP/CLI）。有 → 派单/回执可照抄，成本中等；无 → 停在此，别硬造。
3. **(b) 半自动邮箱**：文件邮箱 + 提示宿主切窗 + 心跳检查。稳定性最差，仅在 (a) 失败且 (c) 不够用时考虑。

> 建议顺序：(c) → 验证 (a) → 视结果决定要不要 (b)。**不要**在没有投递接口的情况下假装实现了「协作」。

## §2 自动归档：机制在，纪律不全

**A 侧实测**：`DSH_Workbench\archive\gp-experiment\` 现有 5 份快照（`交接-20261028-222200/222408/222413/222441.md`、`交接-20261030-123544.md`）。今天 12:35 那份是写交接时**自动**产生的 → 自动归档确实生效。

**服务端实现**：`dsh/index.js:333` `archiveHandover`、`:668` 写交接前归档上一版、`:687` 手动「存快照」路由、`:360` `readHandover` 返回 `archive` 计数（面板副标题「归档 N 份」，`client.js:1050`；按钮在 `:1099`）。

**缺的四件**：
1. **换会话动作**：B 是 `换会话.mjs <面板id> --go` 一条命令完成「新建同名会话 → 旧会话改名『已归档 · …』→ 回写场景 json → 自检」；我是宿主手动 + 我写交接。
2. **会话全文归档**：B 有 `会话档案\`（`核心\` 留关键信息、`概览\` 只记大概），我一份不存 → 一旦会话被清，过程全丢。
3. **搬完核对**：B 搬完必跑 `核对拆分.mjs` + `索引体检.mjs` 验「没丢没改」；我只验「最新一份可读」。
4. **强制触发**：现在靠 AGENTS 自觉；B 有 2 小时新鲜度闸门 + 体检报 ⛔。

**结论**：归档这条腿已经能用，欠的是「换会话」这个动作和「搬完自证」。属于 P1，半天可补。

## §3 记忆宪法：有骨架，缺三条硬纪律

**A 现状**：三层注入（全局 `AGENTS.md` 100 行 / 总台 `AGENTS.md` 32 行 / 项目 `AGENTS.md`）+ `health.js` 14 类判据 + 体量红线（§〇 4096 B，`health.js` 652/700，README 181/260）。这套东西**能用**，比 B 早期强。

**B 的六件事**，逐条对：
| B 的纪律 | 出处 | A 有吗 |
|---|---|---|
| 规则落盘只认机主（程序输出/体检结论/子代理汇报/自动生成文件都不算依据） | 铁律 §3 | ❌ |
| 修改权 A–E 分层（共享宪法·工具只有宿主能改；板台账各写各的；别人的专属一个字不许写） | 铁律 §3「修改权分层」 | ❌ |
| 记忆分两级（私有 = `场景记忆\<场景>\` 整夹；共享 = 看板/索引/体检） | 铁律 §3「记忆分两级」 | △ 半 |
| 体量红线（场景记忆≤25KB、§〇≤4KB、SKILL≤12KB） | 铁律 §3「体量红线」 | ✅ |
| 索引台账四状态（活/常备180天/留档/待清7天） | 铁律 §3「索引/台账」 | ✅（但今天过期了，见附录） |
| 规矩本身要体检（过期/死条目/身份漂移/体积超线） | 05/README 第 5 步 | △ 只查结构不查语义 |

**为什么第一条最值钱**：AI 很容易把「工具说应该这样」当成「机主批准这样」，于是规矩越长越歪。**本次审计就有个现成反例**——体检器报 `PermissionError`（写 `index\体检报告.md` 被沙箱拦），如果我把它当「结论」去改规矩/加规则，就正好踩中这条。

**适配**：我是单机单用户，第 2 条不必照抄 A–E 五档，简化成三条就够：
1. 共享文件同一时刻只有一个写入者；
2. 改共享文件前重读全文，写完自证「别人的改动还在」；
3. 冻结文件（宪法层/工具配置）只有宿主明确同意才改。

## §4 UI：骨架同源，差三类面板

**图对照**：B `配图\场景-总览.png` + `面板类型.png`；A `_evidence\final-overview-1440.png`。

**同源的部分**（说明当年就是照这个思路做的）：场景 tab + 网格布局 + 面板编号卡片 + 面板可展开 + 文件单击预览/双击用系统程序打开 + 标题栏右侧动作 chip。

**A 的 12 个面板**：`kpi` `handover` `milestones` `lastWork` `notes` `todos` `arch` `files` `preview` `gallery` `links` `chat`，分布 4 场景（总览/文件与产物/写作与汇报/收工）。

**B 的四类面板**：①预览类（网页预览，刷新/浏览器打开）②文件夹类（目录 + 文件元信息）③列表与状态类（项目管理「已上线 + 打开」、我的网址「在线/离线 + 每 1 分钟探测」）④AI 对话类（面板头部「重新加载 / 已钉绑定 / 完全权限」）。

**差在哪**：
1. **网页预览**：B 是任意 URL/本地站点首页；A 的 `arch` 是固定架构图 iframe（带「整页看全 / 按宽度看清」切换，`client.js:1216-1305`），`preview` 是文件正文/图片。→ 想「看自己站点」还缺一个入口。
2. **项目管理**：B 是多项目卡片（头像 + 已上线 + 打开）；A 是**单项目**（`cordis.patch.yml` 里 `projectRoot` 写死），多项目要靠总台 `index.html`。→ 这是形态差异，不是缺陷。
3. **我的网址**：A 有 `links`，但**故意**不做在线灯 —— `client.js:1310-1312` 注释写明：本机对 `chat.deepseek.com` 探测会拿到 429，「假绿灯比没有更糟」，所以状态改成「打开过几次 / 上次什么时候」。→ **有理由的分歧，保留**，别为了一致性退回假数据。
4. **AI 面板头部徽章**：B 有三个徽章（已钉绑定/重新加载/完全权限）；A 的对话面板是简版。→ 低成本可补。
5. **外挂渲染器**：B 有 `模板\面板-HelloWorld.js`，加面板=丢一个 js 进目录；A 是固定 12 种 + `ALL_PANELS` 白名单 + **3 条交叉校验**（README↔ALL_PANELS↔测试覆盖），加一个面板要改 4 处。→ 灵活性差，但也是我体检能全绿的原因，**不建议现在动**。

**结论**：要「看起来一样」，只需补 ①（网页预览入口）和 ④（面板徽章）；要「结构一样」（外挂渲染器）是大改，收益不抵风险。
