## 二、目录结构与"每个文件夹回答什么问题"

```
5_Reference/
├─ README.md                     ← 本文件：索引 + 命名规范 + 已推翻结论清单
├─ AGENTS.md                     ← AI 助手操作指南（指向本 README，不再重复维护目录树）
├─ 00_索引与思路历程/              「项目是怎么一步步走到今天的」
├─ 01_选题与方案/                  「为什么做这个题目、最初打算怎么做」
├─ 02_方法学审查/                  「被挑出过什么问题、哪些结论已被推翻、当前权威口径是什么」
├─ 03_论文写作/                    「论文本身」：正文、骨架、表清单、指标说明书、制图脚本
├─ 04_格式与模板/                  「学校给的东西」（不要和你的稿子混在一起）
├─ 05_交付件/                      「能直接交出去的文件」
├─ 06_进展与汇报/                  「给别人看/讲的」：Log、导师会议、科普
├─ 07_文献与技术路线/              「外部依据与前瞻技术」：SPE 库、Omission/LAN+OPN、AutoRA
└─ 99_归档/                        「一次性产物」：旧脚本、code dump、文件分类表
```

**设计原则**：按**文档的生命周期阶段**分，不按文件类型分。同一份文档的多个版本收进该目录下的 `_历史版本/` 或 `_旧稿/`，主线只留最新。

## 四、命名规范（新建文件请遵守）

1. **目录**：`两位数字_中文短语/`。数字 = **阅读顺序**，不是优先级；子目录用 `_历史版本/`、`_旧稿/`、`_抽取文本/`。
2. **文件名**：`主题_版本或日期.扩展名`。日期一律 `YYYYMMDD`（如 `_20260913`），**不要**写 `0913` 或 `9月13日`。
3. **`_` 前缀** = 派生/工作文件（脚本、抽取文本、构建产物），不是给人读的第一入口。
4. **交付件**：`毕业论文_蔡振辛_初稿v{主}.{次}_图版_{YYYYMMDD}.docx`。只有这一种命名格式。
5. **新建文档头部必须包含四行**：
   ```
   > 日期：YYYY-MM-DD
   > 状态：✅现行 / ⚠️部分过时 / 🗄️仅历史 / ❌已被推翻
   > 依据：<上游文件或脚本>
   > 权威性：<这份文件在什么问题上说了算>
   ```
   第 5 条是为了防止再出现"一份文档被当成权威、但它内部自相矛盾"的情况（2026-09-16 审计的 deadline 段落就是这么出问题的）。
6. **新增/移动文档后，回来更新本 README 的 §三 清单。**

| 「lapse 不建模」 | `AGENTS.md` §三、`1_Code/AutoRA_SPE/README.md` §4 | ⚠️ **限定**：三次否证针对的是**"机制化 lapse"（该试次漂移置零，`v←0`）**。Leng et al. 论文用的 lapse 是**"均匀 RT 分布 `1/(2T)`、选择 p=0.5"与 SSM 的混合**——**这一种形式本项目从未测过**。论文 Fig. 5 证明该形式可与 SSM 参数被 OPN **联合识别**，而 g3 的遗漏缺口（观测 .386 vs 仿真 .165）恰属其声称能处理的类型。→ 结论本身不算被推翻，但**不能据此声称"已排除 lapse"**；是否纳入需靠模型比较回答（见 `02_方法学审查/路线B模型规格与遗漏建模路线_20260930.md` §4.5.4 P1-1） |
