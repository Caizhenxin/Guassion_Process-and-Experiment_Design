# 全流程一键跑通：使用说明（数据 → 结果 → 图 → 结果节骨架）

> 适用版本：分析侧 `1_Code/Experiment/run_pipeline.py`（首版 2026-10-18）
> 数据来源：`1_Code/Experiment/exp_matlab/Exp_Design_Formal.m`（v4.9）
> 本文只讲**怎么跑、产物在哪、怎么判断能不能用**；判据本身的出处见
> `Stage6_Pilot方案.md` §5、`Stage8_建模与验证方案.md` §5 与 `工作流_主计划.md` 的决策行。

## 1. 数据目录怎么摆

一个目录 = 一批数据（一名或多名被试、一场或多场）。文件命名必须与程序产物一致：

```
2_Data/Real_Data/<批次名>/
    EXP_data_group<组>_<编号>.csv     # 权威快照（25 列）
    exp_group<组>_subject<编号>.txt   # 孪生原始记录（25 列、制表符）
```

- 组 1–4 对应 P = 0 / 8 / 32 / 120（`qc_group.P_BY_GROUP`）。
- 同一 `(组, 编号)` 只应出现一次；重复快照会被 `intake.py` 判为 `shadowed`
  并显式打印（它取层级最浅的那一份，但**报告里会点名**被忽略的文件）。
- 合成演示数据在 `2_Data/Real_Data/_SYNTHETIC_DEMO_v1/`，带 `synth_truth.json`
  与「这是合成数据」的 `README.md`。**不要让真数据与它混放。**

## 2. 一条命令

```powershell
cd "D:\GitHub_programe\GitHub\Guassion-Process-Experiment-Design"
python -X utf8 1_Code\Experiment\run_pipeline.py "2_Data\Real_Data\<批次名>" --profile quick
```

- `--profile quick`：`n_em=3, n_draws=12, n_x=21, n_ppc=1`。**只用于流程验证**，
  1 小时量级，数值不作结论（尤其 Pareto k 在抽样数 < 25 时无诊断能力）。
- `--profile formal`：`n_em=12, n_draws=50, n_x=81, n_ppc=10`，正式采集用。
  在 8 人 × 561 试次上为数十小时量级，必须后台跑。
- `--skip-stage8`：只跑到 Stage 8 之前（入库 + 达标），不拟合、不出图。
- `--reuse-stage8`：`<out>/stage8/` 里已有 `stage8_group_<组>.json` 时**跳过拟合**，
  只重出图与结果节骨架（改排版/补图注时用，避免几十小时的重跑）。
- `--resume`：断点续跑，已有 `stage8_group_<组>.json` 的组直接复用（交给 `stage8_run.py` 判缓存）。
- `--out`：默认 `<数据目录>/_pipeline`。

## 3. 产物与判读顺序

| 顺序 | 文件 | 先看什么 | 不合格时怎么办 |
|---|---|---|---|
| 1 | `_pipeline/intake_report.md` | 「计入 KEEP」有几场；每场的「说明」列 | 该场剔除，不要靠改阈值救 |
| 2 | `_pipeline/stage6_report.md` | §2 判据汇总里有没有 `FAIL`；§4 结论 | 按 §3 的触发分支处理（回改设计/查 P 档…） |
| 3 | `_pipeline/stage8.log` | 每组每个模型的耗时与 `LOO` 口径 | 失败先看是否 `n_nonfinite`、是否被 `--resume` 缓存挡住 |
| 4 | `_pipeline/stage8/stage8_group_<组>.json` | `results.M-T1.loo.k_diag_ok` | 为 `false` ⇒ 只当流程验证，不能作模型比较证据 |
| 5 | `_pipeline/figures/figures_index.md` | 三张图 + 数值表 | 合成数据的图**不得**进论文结果节 |
| 6 | `_pipeline/results_skeleton.md` | 表格已填好、`【待写】` 是论述槽位 | 直接粘进论文正文再补论述 |

`_pipeline/pipeline_report.md` 汇总四步的退出码、耗时与产物路径——**先读它**。

## 4. 每步调用的既有工具（不复制判据）

| 步骤 | 工具 | 作用 |
|---|---|---|
| 1 | `1_Code/Experiment/intake.py` | 一场能不能计入 N（技术层 / 结构层 / 一致层） |
| 2 | `1_Code/Experiment/stage6_report.py` | 计入的场次合起来是否达 Pilot 判据（S6-1…S6-6） |
| 3 | `1_Code/DDM_Core/stage8_run.py` | 层级 DDM 拟合 + PSIS-LOO + 模型比较 |

| 5 | `1_Code/Experiment/run_pipeline.py` | 编排、汇总、生成结果节骨架 |

## 5. 换成真数据时唯一要改的东西

**不改命令、不改代码**：把 `Exp_Design_Formal.m` 收来的 CSV/txt 放进
`2_Data/Real_Data/<新批次名>/`，把 `<批次名>` 换掉重跑。若目录里没有
`synth_truth.json`，图里就不会画真值线，`results_skeleton.md` 也不会带
「合成数据不得进论文」的声明。

## 6. 已知限制（写论文时必须在限制节交代）

1. **Pareto k 的诊断能力取决于抽样数**：`n_draws < 25` 时 `k̂` 恒为 0，
   `k_diag_ok = false`。此时的 Δelpd 只能当流程验证。
2. **`--profile quick` 的拟合参数不可解释**：EM 迭代 3 次远未收敛，参数图只看「跑得通」。
3. **行为层不依赖模型**：`fig1` 直接由原始文件算，这一张在任何 profile 下都可引用。
4. `stage8_run.py` 只吃 `.txt`（HEADER25）；只有 CSV 的场次能过 1、2 步但进不了 3 步。
