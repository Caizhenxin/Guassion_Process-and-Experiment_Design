# 数据快速筛查 SOP（一条命令判「达标 / 需补」）

> 用途：每收回一批数据（1 场也行、20 场也行）跑一次，回答两个问题——**这批数据能不能算进 N**、**样本量够不够，还差几个人**。
> 唯一入口：`1_Code/Experiment/intake.py`（D95 起源，D120 扩成五层）。所有判据都复用仓里既有工具，不在本文件里另立口径。

## 0. 一条命令

```powershell
python -X utf8 1_Code/Experiment/intake.py 2_Data\Real_Data\<批次目录> `
  --out 4_Reports\筛查_<批次>_<日期>.md `
  --csv 4_Reports\筛查_<批次>_<日期>.csv `
  --json 4_Reports\筛查_<批次>_<日期>.json `
  --expect-n 40
```

- 位置参数可以是目录，也可以是若干 CSV 文件；目录会按 `find_sessions` 递归找 `EXP_data_group(\d+)_(\d+).csv` 与 `exp_group(\d+)_subject(\d+).txt`（同名取层级最浅的一份，其余记为 `shadowed` 警告）。
- `--expect-n`：**每组计划人数**（默认 40），只影响「需补」口径里的计划量，不影响数据判定。
- 退出码：`0` = 没有场次被判不计入；`1` = 有（CI 里就该失败）；`2` = 输入不可用（路径/列缺失）。

## 1. 五层判据（谁硬、谁软、谁只记录）

| 层 | 查什么 | 判据来源 | 失败级别 |
|---|---|---|---|
| ① 技术层 | Stage 1 六项验收 | `exp_Check/check_stage1_acceptance.py` | 硬（6-B、6-C 单行级已降为信息项） |
| ② 结构层 | `qc_group.classify` 裁决、正式段 576 试次、练习段 = P | `qc_group.py` | 硬（`classify`=EXCLUDE）/ 软（练习段行数不符、txt 去重丢弃、缺孪生 txt） |
| ③ 一致层 | 列名/匹配键/P 与组别 | `read_formal_data.validate()` | 硬（列结构）/ 信息（逐行取值异常） |
| ④ 质量层 | 响应率、提前按键、正确率、RT 中位、时长偏差、可用试次率、逐格原始试次 | 本文件阈值表（§3） | 硬 = 软阈值再降一档/ 软 = 记录 |
| ⑤ 统计层 | SPE 三个端点量的 SE 与「需 n」 | 本文件 §4 | 达标 / 需补 |

**三档裁决**：`✅ KEEP`（计入 N）｜`🟠 REVIEW`（可计入，但方法节要报备）｜`❌ EXCLUDE`（不计入，先修程序或重跑）。

**信息项（ℹ）只记录、不阻塞**。理由是硬的：拿行为当剔除理由，等于按结果挑被试，会把组间比较挑成「好被试 vs 差被试」。超时率高、正确率偏低这类偏离一律进信息项与限制节，不进剔除理由。

## 2. 读报告的顺序

1. **§一 结论**：先看「计入 / 待复核 / 不计入」三个数和统计层那句判词。
2. **§二 统计层**：看每个端点量的 SE 与「需 n」。判词取「按组定编」——P 是组间因子，**组内精度不够就等于这条曲线没法定量**，所以总判定要求四组都达标，而不是把 20 人当一个大样本。
3. **§三 逐场表**：非 KEEP 的场次逐个看理由；一列「逐格(原)」是全批最薄的 (T,W) 单元原始试次数，掉到 10 以下就该怀疑那一档的刺激没发出来。
4. **§四 复核清单**：只有 REVIEW/EXCLUDE 的条目，带完整理由。
5. **§五 信息项**：普遍项（过半数场次都出现）单独汇总，剩下的是个别场次的行为偏离。
6. **§六 口径与复现**：阈值和清洗规则都写在报告里，换人跑也能复现同一判词。

## 3. 质量层阈值表（软 / 硬）

| 指标 | 软阈值 | 硬阈值 | 方向 |
|---|---|---|---|
| 时限内响应率 | 0.60 | 0.50 | 低于即异常 |
| 提前按键率 | 0.10 | 0.20 | 高于即异常 |
| 响应试次正确率 | 0.60 | 0.55 | 低于即异常 |
| 清洗后 RT 中位 | 400 ms | 250 ms | 低于即「在瞎按」；高于 400 只记软 |
| 刺激时长偏差 > 20 ms 的试次占比 | 0.05 | 0.15 | 高于即掉帧成片 |
| 可用试次率（清洗后/正式段） | 0.60 | 0.45 | 低于即这场几乎没用 |
| 正式段逐格原始试次 | 12 | 10 | 低于即单元被掏空 |

改阈值只改 `intake.py` 顶部常量（`Q_RESP` / `Q_PREM` / `Q_ACC` / `Q_RT_MED` / `Q_DEV` / `Q_EFF` / `Q_CELL_RAW`），改完重跑，**别在 Excel 里手改报告**。

## 4. 统计层：SPE 到底能不能测出来

- 端点量三个：`ΔRT 中位`（他人 − 自我，ms）、`Δacc`（自我 − 他人，pp）、`分位斜率`（ΔRT 对 RT 分位的回归斜率，ms）。
- 目标精度（`TARGET`）：SE ≤ **10 ms** / **0.03** / **30 ms**。定编公式 `n = (SD / 目标 SE)²`，向上取整；`hire = ceil(1.2 × need)` 是给 20% 损耗留的余量。
- 清洗口径：**只看正式段**（练习段固定 T=83.3/W=1200，混进统计会把 (T,W) 单元计数和 SPE 一起带偏），再取「按期响应且 `120 ms < RT ≤ W + 50 ms`」。
- 判词：四组各自的 `需 n` 求和 = 这批实验的总定编；现有 < 总定编 ⇒ **需补**，并直接把缺口摊到组（「组 1 差 11 人」这种）。

## 5. 边收边查的用法

- **单场交回时**：`python -X utf8 1_Code/Experiment/intake.py <那一场所在目录>`，退出码非 0 就别往 N 里加，先让主试确认是不是跑了两遍/换过机器。
- **一周一次**：对整个批次目录跑 §0 的完整命令，看统计层判词从「需补」变「达标」没有。
- **判词变了要记一笔**：把 `4_Reports/筛查_*.md` 一起提交，报告本身就是批次的可复现快照（含生成命令、阈值、口径）。

## 6. 已知边界

1. **单场判定不能替代组层判定**：`classify` 是组层快检，样本仅 1 场时它只检查该场自身结构，不判组内分布。
2. **阈值是按 20 人批次标的**，样本量再大时可重标（`Q_*` 常量），但改阈值必须在报告 §六 留痕。
3. **统计层默认 P 为组间因子**（`P_BY_GROUP`）；若将来改成组内设计，`stats_layer` 的 `by_group` 分组键要跟着改。
4. **不做推断**：本工具只判「能不能算进 N」「够不够」，不做 SPE 的显著性检验——那是 `real_data_check.py` 与建模管线的事。

## 8. 复现性与边收边查的自检

**同一份数据必须跑出同一个结论**，这是「可信可重复」的底线。两条自检：

```powershell
# ① 连跑两次，JSON 除时间戳外逐字节一致；并与已提交快照比对
python -X utf8 1_Code/DDM_Core/_scratch/check_intake_repro.py
# ② 只交回一场 / 一个组刚开了头，判词不能变「达标」
python -X utf8 1_Code/Experiment/intake.py <单场目录>
```

按这两条验过 2026-10-24 的 20 人批次：两次运行完全一致、与提交快照一致；单场批次判**需补**。

**「样本不足」不等于「达标」**（2026-10-24 修的一个真 bug）：某个端点量在某组里不到 2 人时，
`n = (SD/目标SE)²` 无解，此时结论是「**还没测**」而不是「测够了」——代码里 `block()["unknown"]`
会把该组标成需补、`group_plan` 置 `None`，报告写「定编暂时算不出来，先把每组收到 ≥2 人」。
只有「所有组都有解、且每组 `need_more == 0`」才判达标。

**判据只有一份**：`intake.screen(sessions, expect_n)` 是唯一的裁决函数，`main()` 与
`run_pipeline.py` 的第 1 步都调它。别在别处重写三层/五层逻辑——2026-10-24 就出过一次事故：
`run_pipeline` 只调了 `audit_one`（三层、不含质量层），同一批数据它给 **19/1/0**、`intake` 给 **17/1/2**，
两个入口两个答案。现在两处都走 `screen()`，冒烟脚本 `_scratch/_smoke_pipeline_step1.py` 可复核。
