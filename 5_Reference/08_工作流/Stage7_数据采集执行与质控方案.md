## 1. 目的（主计划原文）

`5_Reference/08_工作流/工作流_主计划.md` §3 Stage 7（L315–318）：

> - 按定稿设计执行，遵守 Stage 1 的记录规范；
> - **每完成一个 P 组就做一次数据质量快检**（不要等收完再查）。

本方案把这两句话落成可执行的规模、清单、判据与工具。

❗ **为什么"不要等收完再查"是硬要求**：本设计的 P 是**被试间** 4 水平，
任何一组的系统性失败（timeout 过高、正确率过低、`RT<T` 结构不对）都意味着
**该组要重招**。若等 160 人收完才发现，损失的是 40 人 × 35 min 的机时与招募成本，
而且**组间 N 会失衡**，直接砸掉 Stage 8 的组层比较。

| Stage | 规模 | 看什么 | 不看什么 |

| **Stage 7** | **4 组 × ~40 人 = 160 人**（招募 192） | **每位被试的可信度 + 四组的可比性**；逐组滚动质控 | 建模（留给 Stage 8） |

## 3. 规模与目标（来自定稿设计）

| 项 | 取值 | 依据 |
|---|---|---|
| 设计 | **P = 0 / 8 / 32 / 120**（被试间 4 水平）× **T = 4 档**（被试内）× **W = 3 档**（被试内） | D4 / D7 |
| 试次 | **576 试次/人**（3 block × 4 T × 4 类 × 12 次），每 `(T,W)` 格 = 4 类 × 12 = **48** | D4 |
| 时长 | **16.5–16.9 min**/人 | 定稿 §2 |
| 每组人数 | **~40**（`beta_P` 要 ~10% 精度需 ~40 人/组） | D31 / D32 |
| 总样本 | **160 人**（4 组 × 40） | D31 / D32 |
| 招募 | **192 人**（+20% 损耗余量） | 定稿 §7 ① |
| 掩蔽 | 统一有掩蔽（`M = 1`） | D6 |
| 按键规则 | 刺激期内按键**立即结束试次**（实际呈现 = `min(T, RT)`） | D5 |

⚠️ **"小规模版本"只允许缩人数，不允许缩 T/W 档数、4 类或 block 数**——
一旦缩了，Stage 7 的 G4（每格 48 试次）就失去意义，且 Stage 8 的 `(T,W)` 逐格 PPC 无从谈起。

## 4. 记录规范（= Stage 1 的 v4.1 规范）

数据文件由 `Exp_Design_Formal.m`（**v4.1，1325 行**）写出，`exp_group{G}_subject{S}.txt`，
**25 列** tab 分隔，首行为表头：

```
groupID subjectID gender age handedness stage trialID P T W Shape Label CorrectKey
Response RT Correct block premature_press timeout responded_by_deadline
stimulus_onset_actual stimulus_offset_actual mask_onset_actual stimulus_dur_actual stimulus_frames
```

不变式（采集期一旦发现违反，立即停该被试）：

1. **时间列单位一律是秒**（`T`/`W`/`RT`/`stimulus_*_actual`）；`P` 是练习试次数。
2. `stage ∈ {practice, formal}`；练习段试次数 = `P`（`P = 0` 时兜底 **4**），正式段 = **576**。
3. 未响应：`Response = NA`、`RT = NaN`、`timeout = 1`、`responded_by_deadline = 0`。
   **不得**出现字面 `0` 或空串（`data` 列 14 直接写 `respStr`，避免 `char(NaN)` 写出 NUL 字节）。
4. `stimulus_dur_actual = mask_onset_actual − stimulus_onset_actual`，
   `stimulus_frames = round(stimulus_dur_actual / FlipIntv)`。
5. **`T`/`W` 必须是 6 位小数**（v4.1 修正）——若 T 列出现 `0.1` 而不是 `0.083330`，
   说明跑的是 **v4 或更早**，**该批数据作废**（`T` 的两档不可区分）。

## 5. 逐 P 组滚动质控（主计划的硬要求）

### 5.1 触发时点

**每收满一个 P 组（约 40 人）就跑一次**；采集期内可选**每天/每 5 人**跑一次滚动版。
命令（`1_Code/Experiment/qc_group.py`，零依赖）：

```
python 1_Code/Experiment/qc_group.py <采集目录> --out qc_<日期>.md
```

* **采集期内不要加 `--final`** ⇒ G1 只报进度（`INFO`），不会因为"还没收满"而假报警。
* **该组收满后加 `--final`** ⇒ G1 人数不足即 `FAIL`，这时才是真的缺人。
* `--expect-n 40` 是默认值；`--groups 1,2,3,4` 默认全报。
* 加 `--json qc.json` 可拿到结构化结果（供后续汇总/画图）。

### 5.2 判据表（G1–G9）

`qc_group.py` 输出；**G1–G9 中任一 FAIL ⇒ 该组必须处置后才能继续**。

| ID | 判据 | 阈值 | 超标后果 |
|---|---|---|---|
| **G1** | 该组**可用**被试数（剔除后） | **≥ `--expect-n`（40）** | 加 `--final` 后为 **FAIL** ⇒ 补招 |
| **G2** | 每被试正式段试次数 = **576** | 全部相等 | **WARN** ⇒ 逐人复核；`< 90%` 直接剔除（提前退出） |
| **G3** | 每被试练习段试次数 = `P`（`P=0` 时 = 4） | 全部相等 | **WARN** ⇒ 查 C6 提示屏与练习分支（`P=0` 的兜底分支也要被执行过） |
| **G4** | 每 `(T,W)` 格 = **48** 试次（4 类 × 12），共 4×3 格 | 严格相等 | **FAIL** ⇒ **先查 T/W 列精度（v4.1）**，再查试次生成 |
| **G5** | 组层 timeout 比例 | ≤ 20% PASS；≤ 40% WARN | **FAIL** ⇒ T 或 W 太长，回改设计 |
| **G6** | 组层正确率 | **0.55–0.98** | **FAIL** ⇒ 任务太难或被试在乱按 |
| **G7** | 组层「**刺激内完成累计**」（`0.15 s ≤ RT < T`） | ≤ 20% PASS | **WARN ⇒ Stage 8 必须扩展为时变输入模型** |
| **G8** | 数据里的 `P` 值 == 该组设计 `P` | 严格相等 | **FAIL** ⇒ **groupID 错配**（组文件放错目录／被试编号重号） |
| **G9** | 帧长估计跨被试一致（`max/min`） | ≤ 1.02 | **WARN** ⇒ 有被试在不同机器/刷新率上跑 |

**G8 是本表里最容易被忽视、后果最重的一条**：它检测的是"文件被放进错的组目录"。
一旦错配，Stage 8 会把一个 P=120 的被试当成 P=0 拟合，**而且不会有任何其它告警**。

### 5.3 为什么要看 G7 而不是 `RT < T` 总比例

与 Stage 6 完全同源（见 `Stage6_Pilot方案.md` §5.1）：`RT < T` 混进两类行为——
**预期性抢按**（`RT < 0.15 s`，刺激刚上屏就按，不是在攒证据）与
**刺激内完成累计**（`0.15 s ≤ RT < T`，这才是需要时变输入模型的理由）。
**短 T 下两者必然混在一起**（`T = 2 帧 = 33.3 ms` 时 `RT < T` ⇔ `RT < 33.3 ms`，必定 < 0.15 s）。
只看总比例会把"短 T 档多"误读成"需要时变输入模型"。

### 5.4 被试处置口径（**事前登记，采集中途不得改**）

| 处置 | 条件 | 含义 |
|---|---|---|
| **保留** | 无下述任何一条 | 进入 Stage 8 |
| **剔除** | Stage 6 的 **S6-3** FAIL（`Response`/`RT`/`responded_by_deadline` 自相矛盾 ⇒ 按键被丢或被误记）**或** 正式段试次 `< 90% × 576`（提前退出）**或** 旧格式文件（非 25 列） | 数据不可用，**必须补招** |
| **待复核** | Stage 6 的其它 FAIL；试次数不等于规格；timeout > 40%；帧长估计偏离组内中位数 > 2% | **不自动剔除**，人工看过再定 |

⚠️ **"待复核"不得当成"剔除"批量执行**：本设计里 `RT<T` 在短 T 档是设计使然，
按总比例一刀切会**系统性地多剔短 T 档**，而短 T 档正是本设计要比较的条件之一。

### 6.2 两个已修的静默失败（教训）

1. ❗ **UTF-8 BOM 会让所有列名退化成 `col1..col25`**（`analyze_pilot.read_table`）。
   `rows[0][0] == "\ufeffgroupID"` ⇒ 表头识别失败 ⇒ 下游把"正式段试次数"读成 **0**，
   **不报错**。若数据被 Excel / 记事本 / PowerShell 重存过，就会撞上。
   已改为 `encoding="utf-8-sig"` + 表头识别容忍前置空列/BOM 残留；
   并加了 `bom_is_tolerated` 用例钉住。
2. ❗ **空可用池会假通过**：`all(...)` 对空序列返回 `True`，
   于是"所有可用被试的每格试次数都合规"在**没有可用被试**时也成立。
   已改为结构类判据（G2/G3/G4）看**全部 v4 记录**，并对空池显式报 FAIL。

## 7. 现场执行清单

1. **确认跑的是 v4.1**（`Exp_Design_Formal.m` 头部 `v4.1`；或开跑后检查第一份数据的 T 列是否为 `0.083330` 一类 6 位小数）。
2. 确认显示器 **60.004 Hz**（帧长 16.6656 ms）；`FlipIntv` 与实测一致（C1/C3 启动自检会打印）。
3. 确认 `groupID` 输入的是 **1–4**，P 由 `P_groups = [0; 8; 32; 120]` 决定（**不要手工选 P**）。
4. 每位被试跑完即检查文件是否生成、行数是否 = 1 + 练习 + 576。
5. **每收满一个 P 组**：`python 1_Code/Experiment/qc_group.py <目录> --final --out qc_g<N>.md`。
6. 有 EXCLUDE ⇒ 立刻补招；有 REVIEW ⇒ 人工看过再定（**不要批量剔**）。
7. 组间 N 失衡（某组可用人数明显低）⇒ 优先补该组。
8. 把每组的 `qc_g<N>.md` **归档**，作为 Stage 9 论文的采集期证据。

## 8. 决策规则

| 触发 | 动作 |
|---|---|
| **G4 FAIL** | 先查 T/W 列精度；若数据是 v4 及更早 ⇒ **该批作废重采**（不可修补） |
| **G8 FAIL** | 定位错配文件并归位；若无法确定归属 ⇒ **剔除该被试** |
| **G7 WARN（某组）** | Stage 8 **必须**按 `Stage6_Pilot方案.md` §8 扩展为**时变输入模型**；并在论文里解释为什么用 CDF 型输入 |
| G5 / G6 FAIL | 回改设计（T 或 W 太长 / 任务太难）；**不要靠删被试把指标做好看** |
| G1 FAIL（`--final` 后） | 补招；补招的被试**仍按同一口径**处置，**不得**为凑数放宽判据 |

## 10. 已知限制

1. **G7 的分界 0.15 s 是行为学惯例，不是本任务的实测值**——若改动，必须重新登记（同 `Stage6_Pilot方案.md` §11 第 5 条）。
2. **帧长自估依赖 `stimulus_dur_actual`**：该列一旦丢精度，自估会偏小（`--flip` 可显式给定）。G9 只查**一致性**，不查正确性 —— 全体一致地错仍会 PASS。
3. **G2/G3 只能发现"试次数不对"，不能发现"试次内容串了"**（例如 T 与 W 配错）。后者靠 G4 与 Stage 8 的逐格 PPC 兜。
4. **本方案不作效应量判断**：160 人的主分析在 Stage 8；`qc_group.py` 里的组层 timeout/正确率只用于**数据质量**，**不得**写进论文当结果。
5. **`--no-subject-check` 会跳过 S1/S6**，此时"待复核"为空是**假象**，不要用该模式做正式质控。
