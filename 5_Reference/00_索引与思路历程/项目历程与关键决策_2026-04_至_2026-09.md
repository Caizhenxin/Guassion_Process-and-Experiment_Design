## 1. 主线：三条线的缠结

这个项目的"思路凌乱"，本质上是三条性质不同的线被写在同一个文件夹里：

| 线 | 它回答的问题 | 时间跨度 |
|---|---|---|
| **A 论文叙事线** | 研究一~四分别证明什么 | 2026-06 至今，一直在变 |
| **B 方法学审查线** | 每一次审查都推翻上一版口径 | 2026-09-02 至今，已经翻了三轮 |
| **C 技术探索线** | GP 三代、Omission/LAN+OPN、AutoRA | 2026-04 至今，多数没有成功 |

**关键认识**：A 线的"成果"经常依赖 B 线的临时口径，而 B 线的口径又依赖 C 线是否跑通。三者耦合在一起，任何一环变化都会让前面写好的数字作废。这就是为什么会出现"同一篇论文里 p=.019 和 p=.145 并存"。

**而唯一稳定的东西是**：真实数据、实验程序、和那条"从设计参数到潜在决策过程"的问题意识。所有推翻都发生在**表述与口径层**，没有一次推翻"这个题目值得做"。

## 3. 分阶段详述

### 阶段一｜起源：把设计参数当成可优化的对象（2026-04 ~ 05-17）

**起点**：SPE 文献几乎都是"效应检验"——在某个设计下验证自我优势存在。本项目换问法：**(P, T, W) 这个空间里，效应是怎么变的？能不能反过来用它挑设计？**

**地基资产**（继承自学姐的 `S2 gen_data_jh.ipynb`）：Sigmoid 理论映射 + DDM 前向仿真。

**做了什么**：
1. 把 88 人历史数据整理成 8 个设计条件，跑 HDDM 层级 DDM，拿到逐条件的 (v_self, v_stranger, a, t, z)。
2. 搭 6 步清洗管线：诊断 → 6 种敏感性策略 → 清洗参数表 → Sigmoid 校准 + GP + LOCV → 行为验证 → 候选设计点。

**当时就出现的三个警告（都很重要，但都被后来的叙事盖住了）**：

| 警告 | 当时读数 | 事后的意义 |
|---|---|---|
| LOCV 失败 | v_self r = −0.09、a r = −0.44、SPE r = −0.09 | 2026-09 用配置 C 重测：仍是 −0.10 / SPE −0.36 → **设计点不足是稳定的结论，不是噪声** |
| Sigmoid 产生不了负 v | 所有分量 ∈ [0,1] 相乘 → v ≥ 0；而 G1/G2/G4 实测 v 为负 | 根源是**身份项的乘性形式**，2026-09-16 才被定性为"函数形式与数据不相容" |
| G1/G2 遗漏率 72% / 54% | 被标为"参数不可靠" | 演变成后来的"遗漏率 >35% 不可接受"准则，以及整条 Omission 支线 |

**决策点（正确的）**：GP 放在**参数层**（Sigmoid 预测 (v,a,t,z) → GP 学参数残差 → DDM 模拟），不放数据层（直接学行为残差）。理由：低维、可解释、有理论约束。

**决策点（⚠️ 后来的代价）**：把"GP 学参数残差"当成**模型的贡献**，而不是"一个待检验的假设"。

### 阶段三｜Omission 支线膨胀（2026-07）

读到 Leng et al.（当时 in prep）关于"忽略遗漏试次会系统性扭曲证据积累建模"的论文后，一口气写了三份文档：可行性分析 → v2 深度解读 → LAN+OPN 实施作战计划（41 KB）。

**这三份文档本身质量不低**，问题在于**它们写的是"将来要做"，却被多版大纲当成了"已经有"**：

- 全仓库**没有任何 pymc/pytensor 代码**，LAN+OPN 从未端到端跑通；

**结果**：论文里凭空多出一个"研究二"，而它当时只有 Censor vs Drop 的对照分析是真的。这是**学术表述风险**，也是 2026-09-02 审查时被点名的项目之一。

### 阶段五｜第二次收敛：十条规则与配置 C（2026-09-12 ~ 09-13）

**触发**：用 Wilson & Collins（2019）*Ten simple rules for the computational modeling of behavioral data* 逐条核对初稿 v2。

**补做的验证**（规则 2/5/6/7）：参数恢复、后验预测检验（PPC）、模型比较、模型恢复、以及**收敛诊断**。

**❗收敛诊断引爆了第三次数字变动**：历史主拟合（单链 3,000 draws / 500 burn-in、`p_outlier = 0.05`）中 **G3 的起始点参数 ESS = 8.6、R̂ = 1.32**，属于严重不收敛。

**于是重跑，做出三方配置对照**：

| 配置 | 抽样 | `p_outlier` | 结论 |
|---|---|---|---|
| A（历史） | 单链 3000/500 | 0.05 | v_self 的 CI 宽度中位数 **2.45** |
| B | 单链 3000/500 | 0 | CI 宽度中位数降到 **1.16** |
| **C（权威）** | **4 链 × 8000/2000** | **0** | 6 个条件核心参数 100% 达标（R̂ ≤ 1.000、ESS ≥ 9,400） |

**关键因果**：问题主因是 `p_outlier`，不是抽样量。而 **`p_outlier = 0.05` 违背了项目自己在遗漏敏感性分析里给出的建议**——即"Censor 编码必须搭配 `p_outlier = 0`"。这是一个"自己的分析结论没有回灌到主分析"的典型失误。

**代价（必须记住）**：

| 位置 | 配置 A | **配置 C** |
|---|---|---|
| 研究一 · SPE_v 组间检验 | F=2.95, **p=.019**, BF₁₀=2.83–3.29 | F=1.72, **p=.145**, BF₁₀=1.03（**不显著**） |
| 被试间 SD | 1.28 | 0.62 |
| 研究三 · Sigmoid α₁ | 0.862（+86%） | **0.153（+15%）** |
| 研究三 · β₁ | +0.328 | **−0.631（再次反号）** |
| 校准 RMSE | 1.090 | **0.704** |
| LOCV | v_self −0.03 / v_stranger +0.19 / a −0.29 | v_self −0.10 / v_stranger **+0.80** / a **+0.77** |
| PPC 覆盖率 | .167/.278/.333/.333 | **.111/.056/.000/.389**（仍失配） |
| 收敛 | G3 严重不达标 | **全部达标** |

**叙事因此改写**为："行为层稳健、参数层不显著、生成模型需扩展"。

**产出**：`干净章节骨架`、`必须补的表清单`、`图表与指标说明书`、`规则5与规则7段落`、`样本量扩充至20人的分析计划`、v3 与 v3.1 docx。

**同期**：SPE 数据库分析改用**数据库本体**（`D:\GitHub_programe\GitHub\SPE_Database`）而不是旧的中文文档，得到 25 数据集 / 2,488 人 / 337,050 试次 / SPE_RT −93.8 ms（25/25 自我更快）。

### 阶段七｜GP × AutoRA 与 deadline 更正（2026-09-17 ~ 09-21）

**触发**：有一位在招 AutoRA（自动化实证研究）方向博士生的老师，你想把 GP 换槽真正落到闭环里。

**定位（讨论后确认）**：AutoRA 是**确定性代码框架**，闭环 `Experimentalist × Experiment Runner × Theorist × 冻结 Objective` **不消耗任何 token**；token 只花在开发这套代码、以及让 LLM 解读结果。

**Phase 0 验收**（`1_Code/AutoRA_SPE/check_simulator.py`，D1–D7 七项检查）——这是"在谈优化之前先证明前向仿真器是对的"。

**❗验收过程中发现：`deadline` 口径一直是错的。**

- 我的模块初版写 `T + 200 + W`；
- 2026-09-16 审计 §5 P0-1 也写"统一为 `T/1000 + 0.2 + W/1000`"；
- **但实验源码写得很清楚**：`Exp_Design_Formal_v2.m` L20 `deadline 同为 T+W=1.2s`、L513 `反应窗口 W - maskDuration`、L963 `while GetSecs() - responseFlipTime < W - maskDuration`；
- 实测独立确证：8 组最大反应 RT ≈ **T + W + 2 ms**；遗漏率与"窗口时长 W−200"精确对应（g3/g4 同为 400 ms → 遗漏 .386/.384；g7/g8 同为 600 ms → .143/.147）。
- **且审计报告在同一段里自相矛盾**——它把 `sim_utils.py` 的 `(T+W)/1000` 标为 ✅，又说要统一成加 200 ms 的版本。

→ **正确口径：`deadline = T + W`。** 设计表里的 `W` 不是"窗口时长"，而是"窗口关闭时刻"。

**副产物（一条完整的否证链）**：验收中发现仿真遗漏率只有实测的 1/5~1/2，先后尝试被试间变异、跨试次漂移变异 `sv`、机制化 lapse（v←0）三种解释，**全部被否证**；改对 deadline 后遗漏率 MAE 从 0.121 降到 0.072、正确率误差从 0.068 降到 0.047，**同时改善**。所以审计报告"去掉 lapse"的结论其实是对的——只是当时没人拿得出证据，因为口径错误把机制问题伪装了出来。

**Phase 0 判定**：模拟器现在可用于设计优化（时序 ✅、RT 下界误差 3 ms ✅、遗漏率 5/6 ✅、无 lapse ✅）。唯一遗留：**g3（P120/T30/W600）的 v 不可识别**（后验跨度 [−7.73, +3.31]），而这是**研究问题**而非缺陷。

## 4. 为什么这些结论会错：四类错误模式

> 这一节比时间线更重要。**推翻本身不可怕，可怕的是同样的错误模式再犯一次。**

| 模式 | 实例 | 防法 |
|---|---|---|
| **① 口径未锁定就写进"权威文档"** | `deadline` 口径被审计报告宣布"统一"，但没人回实验源码核对；配置 A/B/C 三套数字并存 | 任何"统一口径"结论必须**回到一手证据**（实验源码、原始数据），不能靠文档间互相引用 |
| **② 同一段内自相矛盾** | 20260916 审计既说 `sim_utils` 的 `T+W` 是对的，又要求改成 `T+0.2+W` | 文档头部写"权威性"声明；写完自查同一段是否前后冲突 |
| **③ 把"探索失败"改写成"模型贡献"** | GP 残差支线：LOCV 早就失败，却仍以"GP 补残差提升预测"进入正文 | 负面结果**原位保留**；GP 这类组件要自己证明配得上（做消融对比） |
| **④ 把"规划"写成"方法/已完成"** | LAN+OPN：只有规划文档，被大纲写成"首次应用" | 全文统一四态标记【已完成/初步/规划/展望】 |
