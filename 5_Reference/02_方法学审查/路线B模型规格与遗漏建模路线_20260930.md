## 0. 一句话结论

路线 B 的落地成本比预期低得多：`sim_utils.simulate_trials` **已支持逐试次 `v`**，所以刺激编码**零改动**即可实现（调用侧把 `v` 乘上 `±1` 的刺激符号即可）。但落地前必须先修两处已存在的错误：**既有 `Python_HDDM_Nonmatching` 的模型设定在数学上与数据不相容**，且**遗漏试次被伪造为"恰好在 deadline 按了错误键"**。

## 1. 模型总体结构

三层，自外向内：

```
第 1 层  实验设计（给定）  P, T, W  →  deadline = T+W；窗口开启 = T+200；掩蔽 = 200ms
第 2 层  逐试次生成（本文件主体）
         ┌ 抽试次：身份 A ∈ {self, stranger}，刺激 S ∈ {matching, nonmatching}
         ├ v = v_base(P,T) + Δv·I[A=self]          ← 证据质量（正确性编码）
         ├ z = (z0 + Δz·I[A=self]) · a             ← 匹配键偏向（按键编码）
         ├ a = a(M) + Δa·I[A=self]
         ├ t0 = 常数（跨条件恒定）
         └ 带符号漂移 μ = v · sign(S)，  sign(匹配)=+1，sign(不匹配)=−1
第 3 层  观测（三类，互斥且完备）
         ├ 命中上界（按匹配键）      → RT, response = Matching
         ├ 命中下界（按不匹配键）    → RT, response = NonMatching
         └ 到 deadline 仍未触界      → omission（RT 缺失，不是一个反应）
```

**上界恒为「匹配键」**，与刺激条件无关——这是 `z` 的含义在两种刺激下保持一致的原因。

## 2. 编码规则

### 2.1 正确编码：`v` 按正确性、`z` 按按键

设上界 = 匹配键、下界 = 不匹配键，`z` 自下界量起（`z > a/2` = 偏向匹配键）。

| 刺激 | 正确响应 | 漂移方向 | 起点 `z` 的效应 |
|---|---|---|---|
| 匹配 | 按匹配键（上界） | 向**上** | `z > a/2` → 更快更准（有利） |
| 不匹配 | 按不匹配键（下界） | 向**下** | `z > a/2` → 更慢更差（有害） |

- `v` 是**证据质量**：加性身份项 `Δv` 对两列**同号**。
- `z` 是**匹配键偏向**：加性身份项 `Δz` 对两列**反号**。

**这两个符号关系就是路线 B 的全部价值**：一列同向、一列反向，`Δv` 与 `Δz` 天生可分。

### 2.2 ⚠️ 必须修正：现有 `Python_HDDM_Nonmatching` 的模型设定与数据不相容

现有流程（`1_Code/Python_HDDM_Nonmatching/README.md`）用：

```python
hddm.HDDM(df, depends_on={"v": "identity"}, include=["v","a","t","z"], bias=False, p_outlier=0.05)
```

即**匹配与不匹配共用同一个 `v` 与同一个 `z`**（response 编码，不是正确性编码）。该设定有一个可证伪的硬后果：

> 扩散过程命中上界的概率 `p_up` 是**同一个人在同一次设置下**的同一件事，
> 因此 `P(判断为 Matching | 匹配试次) ≡ P(判断为 Matching | 不匹配试次)`，
> 等价于 **`P(正确 | 匹配) + P(正确 | 不匹配) ≡ 1`**。

实测（87 人，`_scratch/check_single_v_consistency.py`）：

| 身份 | P(判断为Matching｜匹配) | P(判断为Matching｜不匹配) | 差值 |
|---|---|---|---|
| self | 0.834 | 0.318 | **+0.516** |
| stranger | 0.701 | 0.306 | **+0.395** |
| 合并 | 0.770 | 0.312 | **+0.458** |

| 身份 | P(正确｜匹配) | P(正确｜不匹配) | 之和（理论必为 1） | 偏离 |
|---|---|---|---|---|
| self | 0.834 | 0.682 | **1.516** | +0.516 |
| stranger | 0.701 | 0.694 | **1.395** | +0.395 |
| 合并 | 0.770 | 0.688 | **1.458** | +0.458 |

**偏离 0.46，远超任何估计噪声。结论：单 `v` 设定在数学上无法产生这份数据。**

> 直觉解释：正确性编码下，"命中正确边界"在两种刺激里指向**不同的物理边界**，
> 所以两个正确率**不互补**、可以同时很高；而单 `v` 设定强制它们互补。
> 观测到的 0.834 / 0.682（同为高值）只有在漂移方向随刺激翻转时才可能出现。

⚠️ **与此相关的既有产物全部需要重做**：`2_Data/Real_Data/HDDM_Traces_Nonmatching/` 下 8 组 `*_stats.csv` / `*_traces.npz` 已完成，但它们建立在该错误设定上，**不得引用**。

**最小修正（保持 HDDM 不变）**：`depends_on={"v": ["identity", "condition"]}`（四格各自一个 `v`）。
**推荐修正（可解释）**：改用 §2.1 的刺激编码，把 `Δv` 与 `Δz` 显式作为要检验的量。

## 3. 参数化

### 3.1 参数表

| 参数 | 含义 | 默认/初值 | 来源与约束 |
|---|---|---|---|
| `base_scale_v` | `v_base` 总体尺度 | 0.774 | 配置 C 的 (v_self+v_stranger)/2 跨条件均值 |
| `T0`, `k_T` | `v_T(T)` 半效点与陡峭度 | 100, 0.01 | 先验占位；T 只有 4 个水平 |
| `P1`, `P0`, `gamma`, `k_at_low_P`, `k_at_high_P` | `v_P(P)` 二阶 S 型 | 4, 32, 0.1, 0.01, 0.15 | 先验占位；**P 嵌套于条件，不可识别，只主张方向** |
| **`Δv`** | **身份 → 漂移（加性）** | 0.428 | ★核心量；(v_self − v_stranger) |
| `base_scale_a`, `M0`, `k_a` | `a(M)` | 1.5, 900, 0.002 | 先验占位；`a(M)` 在多设计点上不可识别 |
| **`Δa`** | 身份 → 边界 | **0（初期固定）** | 用模型比较决定是否放开 |
| `t0` | 非决策时间 | 0.20 | 窗口门控生效后应跨条件恒定 |
| **`z0`** | **基线匹配键偏向** | **自由（初值 0.5）** | ★见 §3.2 第 3 条，**不能固定 0.5** |
| **`Δz`** | **身份 → 起点偏向** | 自由（先验 N(0, 0.1)） | ★核心量，`Δz` 即"匹配键偏向"成分 |
| `sv` | 试次级漂移标准差 | 0（可选纳入） | 有理论动机；但不得再被当作"遗漏缺口的补丁" |
| `sd_*` | 被试级随机效应 | 见 `spe_design_model.DesignParams` | 分层建模用 |

**已由设计固定、不作为自由参数**：`deadline = T + W`、窗口开启 = `T + 200`、掩蔽 = 200 ms、`lapse_prob = 0`（三次否证后确认，见 `1_Code/AutoRA_SPE/README.md` §4）。

### 3.2 参数化细节（四个必须现在定下来的选择）

1. **身份项必须加性**。`v = v_base + Δv·I[A=self]`（沿用 AutoRA 线已做的修改）。乘性 `×(1+α)` 强制两身份的漂移比在所有设计点相同，与实测逐条件 Δv（−0.16 ~ +0.71）不相容，且反推出的 `α₁−α₂` 跨条件漂移 5 倍以上。

2. **`Δz` 先取常数（1 个参数）**，不随 P/T/W 变化。理由：身份对比是**条件内**对比，8 个条件里每个条件都已经能给出一个 `Δz` 估计；再让它随设计变化会立刻超出可识别范围。「`Δz` 是否随设计变化」应作为 AutoRA 的设计优化问题，而不是现在拍一个函数形式。

3. **`z0` 必须自由估计，不能固定 a/2**。这是路线 A 与路线 B 的关键分界：本数据**整体就偏向匹配键**（匹配列正确率 73.7% > 不匹配列 62.7%，合并 `c` 偏离 0）。若把 `z0` 钉在 0.5，这份"整体偏向"在刺激编码里**无处可去**，会被错误吸收进 `v`——因为 `v` 在两种条件下符号相反，表达不了"两列都偏向匹配键"。

4. **`Δa` 初期固定为 0**，`sv` 初期取 0。两者都用**模型比较**（§3.4）而非先验断言来决定。

### 3.3 可识别性：`Δv` 与 `Δz` 的分离公式

设 `SPE_cell` = 某格"自我 − 陌生人"的效应（用正确率、`H`、或 `d′` 都可）。由于

| | 匹配列 | 不匹配列 |
|---|---|---|
| `Δv` 贡献 | + | + |
| `Δz` 贡献 | + | − |

可得两条正交的线性组合：

```
证据成分  ∝ ( SPE_匹配 + SPE_不匹配 ) / 2
偏向成分  ∝ ( SPE_匹配 − SPE_不匹配 ) / 2
```

用本数据的正确率代入：`SPE_匹配 = +14.2 pt`、`SPE_不匹配 = −1.4 pt`
→ **证据成分 ≈ +6.4 pt，偏向成分 ≈ +7.8 pt**，与 SDT 分解（Δd′ = +0.41、Δc = −0.24）方向一致。

### 3.4 必须做的模型比较（逐层放开的消融）

| 模型 | 与 M0 的差别 | 检验的问题 |
|---|---|---|
| **M0** | 单 `v`、`z ≡ 0.5`（= 现有设定） | 基线（预期被否证，见 §2.2） |
| **M1** | `v` 依 `condition`（四格漂移） | 可解释性仍差，但能拟合 |
| **M2** | 刺激编码：`v` + `z0` 自由 | 整体匹配键偏向是否显著（预期显著） |
| **M3** | M2 + `Δv` | 证据优势成分 |
| **M4** | M3 + `Δz` | **偏向成分（本项目的核心待检假设）** |
| **M5** | M4 + `Δa` / `sv` | 是否还有残余结构 |

判据：WAIC / LOO + 四格的后验预测检验（正确率、RT 分位、遗漏率三者须同时对齐）。

### 3.5 生成器落地：**零改动**

`sim_utils.simulate_trials` 的 `v` 参数已支持逐试次的数组（`x[idx] += v[idx] * dt + ...`），因此刺激编码**不需要改仿真器**，只需在调用侧构造：

```python
sign  = np.where(is_matching, +1.0, -1.0)          # 刺激符号
v_pt  = (v_base + delta_v * is_self) * sign        # 逐试次漂移（正确性编码）
z_pt  = (z0 + delta_z * is_self) * a               # 逐试次起点（按键编码，>0.5a 为匹配键偏向）
sim   = simulate_trials(v_pt, a, t0, z_pt, deadline, n_trials, rng)
```

需扩展的是 **`simulate_condition_block`**：目前只按身份分块，需再按 `condition` 分块，并输出 `condition` 与 `correct` 两列。**这一步与"遗漏输出"应当一起改**（见 §4.3 阶段 1）。

## 4. 遗漏率建模路线

### 4.1 现状（诚实盘点）

| 事项 | 状态 |
|---|---|
| OPN 模型 | ✅ **已训练**（`2_Data/Generate_Data/OPN_Training/opn_model.joblib`）。fast 模式，5 特征 `(v,a,t0,zr,deadline)`，**test R² = 0.986 / MAE = 0.017**（2026-07-21） |
| LAN | ❌ 未训练（本项目用恒定边界，解析 Wiener 似然可用，故不需要） |
| **接入似然** | ❌ **完全未接入**。OPN 至今没有出现在任何拟合流程里 |
| 现有遗漏处理 | ⚠️ 只有 Censor（`rt = deadline`、`response = 0`）与 Drop（删行）两种，均未使用 OPN |

所以"OPN 没跑通"这个判断需要修正为：**OPN 跑通了，但从未被接进任何似然**；缺的是集成，不是训练。

### 4.2 ⚠️ 必须先修：现有流程把遗漏伪造成了"恰好在 deadline 按错键"

`1_Code/Python_HDDM_Nonmatching/step1_prepare_data.py` L55–65：

```python
df_f["rt"] = np.where(df_f["omission"] == 1, df_f["deadline"], df_f["RT_num"])
df_f["response"] = np.where(df_f["condition"] == 1, df_f["Correct"], 1 - df_f["Correct"])
```

遗漏试次的 `Correct` 恒为 0，于是 `response = 1 - Correct` 使其**永远落在"错误"那一侧**。
实测 group3（P120/T30/W600）：5200 个正式试次中 1978 个是遗漏（38.0%），**全部 `rt` 精确等于 0.630 s（= T+W）**，且 `response` 与 `condition` 一一对应（condition=0 → response=1；condition=1 → response=0）。

**后果**：38% 的试次被伪造为"在截止时刻犯了一个错"，这会系统性把 `v` 压向 0、把正确率拉向 0.5。这是比"忽略遗漏"更严重的偏差（Leng et al., 2025 论证的是忽略就有偏，这里是反向注入）。

> 加重情节：现有 `HDDM_Ready/`（仅匹配版）用 `response = Correct`，遗漏同样变成"错误"。
> 两次拟合的遗漏口径不同（一个恒错、一个恒按错键），**跨版本比较本身也不成立**。

### 4.3 四阶段路线

#### 阶段 0（已完成，2026-09-17）
修正 `deadline` 口径为 `T + W` + 反应窗口门控 → 遗漏率 MAE 0.121 → **0.072**，同时正确率 MAE 0.068 → 0.047。**说明遗漏缺口主因是口径，不是缺机制**（`lapse_prob` 保持 0）。

#### 阶段 1（下一步）：把遗漏接进似然，并做三臂对比

对恒定边界 DDM，**遗漏概率可解析计算，不需要 OPN**：

```
p(omission | v, a, z, deadline) = 1 − F_up(D) − F_lo(D),     D = deadline − t0
```

首达时分布的 CDF 有公开的快速数值实现（Navarro & Fuss, 2009；Python `wiener` 包的 `cdf`，`pyddm`、HDDM 内部亦有）。**但必须先用自家 `sim_utils.simulate_trials` 交叉校验该 CDF 的实现精度**——这是唯一能避免"第二套事实来源"的做法。

若不想依赖解析式，**更稳的替代是"用自家仿真器预计算查表"**：`p(omission)` 是 `(v, a, z, deadline)` 上的光滑函数，网格 + 插值即可，且**可以逐点与 `sim_utils` 对账**，不存在"NN 学得对不对"的循环问题。这其实就是 OPN 的作用，只是把神经网络换成可验证的插值。

三个臂必须同时报告：

| 臂 | 遗漏处理 | 说明 |
|---|---|---|
| **Drop** | 删除遗漏行 | 现行常见做法，Leng et al. 证明有偏 |
| **Censor** | `rt=deadline, response=0` | 项目现行做法；在四格设计下**须改为不指定方向**（见 §4.2） |
| **Omission-aware** | 遗漏进似然（解析 CDF 或查表） | 目标方案 |

#### 阶段 2：处理"窗口开启前完成决策"的点质量

本实验 RT 自**刺激起点**计，而按键窗口 `[T+200, T+W]`。因此观测 RT 与潜在决策时间 `τ` 的关系是

```
观测 RT = max(τ, T+200)     若 τ ≤ T+W；否则遗漏
```

这产生一个**在 `T+200` 处的点质量**：`P(RT = T+200) = P(τ ≤ T+200 − t0)`。
不显式处理它，似然就是错的——在窗口最短的条件（g1 有效窗口仅 100 ms）里尤其严重。
（`spe_design_model.apply_window_gate` 已在**仿真侧**实现了这个门控，现在需要的是**似然侧**的对应项。）

#### 阶段 3（可选，仅在模型比较支持时才做）：塌缩边界 → LAN + OPN

Leng et al. 认为含 deadline 的任务更适合**塌缩边界**（ANGLE / WEIBULL）。这类模型的 post-deadline 概率质量**没有解析式**，HDDM 也不原生支持——**这才是 LAN + OPN 真正被需要的地方**。届时：
- LAN 提供 `rt ≤ d` 的条件似然（替代解析式，支持任意 SSM）
- OPN 提供 `log p(omission | θ, d)`
- 联合对数似然：`Σ_D f_LAN(rt_i | θ) + |O| · f_OPN(omission | θ, d)`

也就是说：**OPN 是阶段 3 的工具，不是阶段 1 的必需品。** 现在把它接进恒定边界模型，是在用更重的机器做一件解析式能做的事。

#### 阶段 4：写成论文的正式表述

把遗漏从"缺失值"改述为**第三类反应**（与"按匹配键""按不匹配键"并列），并报告：
- 三臂（Drop / Censor / Omission-aware）的参数差异与不确定度
- 遗漏率对参数的敏感性（哪些设计点上遗漏携带的识别信息最多）
- 结论口径：遗漏是设计的**结果**，不是要去掉的噪声

### 4.4 验收标准

四项同时满足才算通过：

1. 按条件的**遗漏率**与观测对齐（阶段 0 已达 MAE 0.072，纳入似然后不应变差）
2. **responded 正确率**对齐（阶段 0 的 0.047 不应变差）
3. **RT 分位**（q10/q30/q50/q70/q90）对齐
4. 报告 **Omission-aware vs Drop 的参数差异**——若差异可忽略，那本身就是一个值得写的结论；若显著，则必须用 Omission-aware 作为主口径

### 4.5 OPN 现状审计（2026-09-30）

> 复核脚本：`_scratch/check_opn_data_provenance.py`、`_scratch/check_opn_interface_fitness.py`（均只读）
> 依据论文：Leng, Fengler, Shenhav & Frank, *The Perils of Omitting Omissions when Modeling Evidence Accumulation*（本地 PDF，21 页）

#### 4.5.1 论文的接口契约（三条）

论文 Equation (6)：

```
log l(D, O | θ_SSM, d) = Σ_{i=0}^{|D|} f^LAN_{c_i}(rt_i | θ_SSM)  +  |O| × f^OPN(omission | θ_SSM, d)
```

| # | 契约 | 论文原文依据 |
|---|---|---|
| 1 | **LAN 只在没有解析似然时才必需** | "we use the LAN as the likelihood for all observed responses … even though analytical likelihoods are available for the standard DDM case … all of our comparisons to the 'LAN only' approach would apply equally for analytic likelihoods" |
| 2 | **OPN 输入 = `θ_SSM` + deadline `d`；输出 = 遗漏的对数似然** | Fig. 1B caption："the OPN provides a function `f_OPN` for the log-likelihood of omissions, given a deadline setting" |
| 3 | **lapse 是「均匀 RT 分布」，与 SSM 混合** | `f_Lapse(t) = 1/(2T)`，`t∈[0,T]`，`T=5s`，每选项 p=0.5；`likelihood = (1−p_lapse)·likelihood_SSM + p_lapse·f_Lapse` |

论文的数值实验设定：`z` 固定 0.5、`τ` 固定 0.3 s、deadline 1.25 s；边界用 `±a`（分离度 = 2a）。
论文主结论：**LAN-only 会低估 `a`、高估 `v`；遗漏率低至 5% 以下就已产生显著偏差**；恒定边界下 LAN+OPN 能恢复参数（其 Figure 2）。

#### 4.5.3 做对的部分（6 条，均经实测确认）

1. **只训 OPN、不训 LAN** —— 与论文契约 1 一致，是本项目该做的选择。
2. **OPN 把 `t0` 与 `zr` 当输入** —— 比论文更完整（论文把二者固定），适用面更广。
3. **`decision_budget = deadline − t0`** —— 与 `sim_utils.simulate_trials` 的 `t_candidate = t0 + step·dt ≤ deadline` 判定一致。
4. **边界约定 0..a、`z` 取相对值** —— 与 `sim_utils`、HDDM 自洽（论文用 `±a` 即分离度 2a，是 2 倍关系；只要训练与拟合同约定就无妨）。
5. **反应窗口门控不影响遗漏事件** —— 门控只把完成的决策推迟到窗口开启（`rt ← max(τ, T+200)`），不改变 `τ ≤ deadline − t0` 这个判定。**所以 OPN 侧无需改**；需要改的是 Wiener 似然侧的 `T+200` 点质量（本文件 §4.3 阶段 2）。
6. **存档训练数据来自正确代码路径** —— 实测：随机抽 25 组参数用 `simulate_ddm_batch_vectorized` 重算，与存档 `y` 的差值均值 **+0.0001**、标准差 0.0021（纯仿真噪声）。即训练时用的是无 numba 的环境。

#### 4.5.4 必须修的问题

##### 🔴 P0-1｜numba 路径的遗漏计数 bug（潜伏但已上膛）

`opn_simulator.py` 的 `_simulate_ddm_batch_numba_kernel`：

```python
if x[i] >= a_f:
    active[i] = False
elif x[i] <= 0.0:
    active[i] = False
    omission_count += 1        # ← BUG：下边界命中是「正常反应」，不是遗漏
...
omission_count += int(active.sum())   # 真正的遗漏
```

**实测（同参数 `v=1, a=1, z=0.5, t0=0.2, d=1.0, n=20000`）**：

| 实现 | 遗漏数 | 遗漏率 |
|---|---|---|
| `simulate_ddm_batch_vectorized` | 451 | **2.26%** |
| `simulate_ddm_batch_numba` | 5483 | **27.42%** |
| 差值 | 5032 | 恰为下边界命中数 |

即 numba 路径把"命中下边界的正常反应"计入遗漏，**误差量级取决于参数（可低可高），不可忽略**。

**为什么现在还没炸**：系统 Python（3.14.3）没装 numba，所以走 vectorized（正确）路径，存档数据是对的。
**为什么危险**：`1_Code/.venv` 里**装着 numba 0.65.1**，而 `README.md` 明确推荐 `pip install numba`（"强烈推荐"）。任何一个用该 venv 的人重跑 `opn_train.py`，训练数据会**静默**变成垃圾。

**修法**：删掉那行 `omission_count += 1`；并在 `simulate_ddm_batch_numba` 入口加一条自检——用固定参数与 vectorized 版对账，相对偏差 > 2% 就抛异常。

##### 🔴 P0-2｜训练先验的零膨胀 → 项目关心区系统性低估

先验 `t0 ∈ (0.1, 0.7)` × 5 维均匀采样，导致 56.6% 的样本落在 `y < 0.01` 的"几乎不遗漏"区。后果（测试集 n=940）：

| 区间 | n | 占比 | MAE | 该区真值均值 |
|---|---|---|---|---|
| y < 0.01 | 532 | 56.6% | 0.0046 | 0.0010 |
| 0.01 ≤ y < 0.05 | 117 | 12.4% | 0.0149 | 0.0244 |
| 0.05 ≤ y < 0.2 | 127 | 13.5% | 0.0239 | 0.1059 |
| **0.2 ≤ y ≤ 0.8** | 116 | 12.3% | **0.0321** | 0.4004 |
| y > 0.8 | 48 | 5.1% | 0.0329 | 0.9393 |

- 报告的 **R² = 0.986 主要是"零区蒙对"贡献的**，不能作为通用精度的证据。
- 项目关心区（0.2–0.8，正是你 30%–50% 遗漏率的所在）MAE ≈ **0.032，是零区的 7 倍**。
- 蒙特卡洛噪声底（`n_sim=5000`）≈ 0.0071，故网络误差**显著高于噪声底**，属真实模型误差。
- **在 6 个真实条件上表现为系统性负偏**（见下表），即 OPN 会**低估**遗漏概率。

**修法（按性价比）**：
1. **改用项目专属先验**再做一次训练。项目实际只用 `t0` 的一个窄区间、`deadline ∈ {0.33…2.0}`、`a ∈ 1.1–2.4`，5 维均匀先验中绝大部分样本是浪费的。收窄先验可在同等样本量下把关心区 MAE 降一个量级。
2. 排除退化端点（`zr` 恰好 0 或 1 时起点落在边界上）。当前 `DEFAULT_PRIOR_RANGES["z"] = (0.0, 1.0)` 含端点。
3. 提高 `n_sim`（5000 → 20000），把噪声底压到 0.0035。
4. **替代方案**：既然阶段 1 只需要 `(v,a,t0,zr,d) → p_omission` 这一张光滑 5→1 映射，且 `sim_utils` 能直接算它，**用网格 + 插值（或直接在线仿真）比神经网络更可控**——可逐点对账，没有"网络学得对不对"的循环论证。OPN 的价值在阶段 3（塌缩边界无解析式）才真正体现。

##### 🟠 P1-1｜与论文的 lapse 混合分布未对齐（口径不同）

- 项目三次否证的是**"机制化 lapse"**（该试次漂移置零，`v←0`），见 `1_Code/AutoRA_SPE/README.md` §4。
- 论文的 lapse 是**均匀 RT 分布**：`f_Lapse(t) = 1/(2T)`，`t∈[0,5s]`，每选项 p=0.5，与 SSM 按 `p_lapse` 混合。

**这是两种不同的形式，论文那一种本项目从未测过。** 而 g3 的遗漏缺口（观测 .386 vs 仿真 .165）恰是论文声称 lapse 混合能处理的那类问题。

**修法**：把"SSM + 均匀 lapse 混合"作为 M0–M5 之外的一条并列模型臂纳入比较（论文 Fig. 5 证明 LAN+OPN 能**联合识别** `p_lapse` 与 SSM 参数，而 LAN-only 会低估 `p_lapse`）。若拟合出 `p_lapse ≈ 0`，则反向支持现有"不建模 lapse"的结论；若显著，则必须纳入。

##### 🟠 P1-2｜`plot_training_diagnostics` 是坏代码

`opn_evaluate.py` L198：`feature_sensitivity_analysis(None, None, i, ...)` 传 `opn=None, scaler=None` → 内部 `None.transform(...)` 必抛 `AttributeError`。主入口用的是 `plot_full_diagnostics`（其 `try/except` 兜住了），所以没暴露。该函数应删除或补上参数注入。

##### 🟡 P2-1｜`p_outlier` 口径冲突 + 与遗漏项双重计入

`Python_HDDM_Nonmatching` 用 `p_outlier=0.05`，项目主口径配置 C 用 `p_outlier=0`。
更要紧的是：HDDM 的 `p_outlier` 是一个**均匀污染分布**，与 OPN 的遗漏项在语义上**重叠**（都吸收"极慢/无反应"的试次），叠加会导致双重计入。
**修法**：接 OPN 之前先把 `p_outlier` 固定为 0。

#### 4.5.6 接入似然的接口约定（可执行契约）

```python
# 目标：logL = Σ_观测 log f_Wiener(rt_i | θ_cell)  +  Σ_cell n_om(cell) · log p_OPN(θ_cell, d)
# 其中 cell = (被试 × 身份 × 条件) —— 必须逐格，不能用被试级单一 v
```

| # | 条款 | 理由 / 陷阱 |
|---|---|---|
| **C1** | **逐格而非逐块**：每个 `(被试, 身份, 条件)` 单元格各算一个 `p_OPN`，分别乘以该格的遗漏数 | 论文用 `\|O\| × f^OPN(...)` 是块级，因为其模拟只有一套参数；**本项目 `v_self ≠ v_stranger`，两格遗漏概率不同，用被试级单一 v 会错** |
| **C2** | `a` 是**分离度**（0..a），不是论文的 `±a`；`zr` 是**相对起点** (0,1) | HDDM 迹线里 `z` 存为 `z_trans`（probit），**必须用 `Φ` 还原**（`sim_utils.z_from_trans`） |
| **C3** | `t0` 与 `deadline` 必须同一时间原点（刺激起点），`deadline = T + W`，`t0` 即 HDDM 的 `t` | 两处口径任一写错，`p_OPN` 全盘错位 |
| **C4** | 取 log 前先 clip：`log(clip(p, 1e-10, 1−1e-10))` | README 已写对 ✓；但注意 P0-2 的 0.03–0.05 负偏会**直接进 logL**（`p=0.3` 处相当于 17% 相对偏差），故必须先修 P0-2 或改用查表 |
| **C5** | `rt_obs = max(τ, T+200)`，而遗漏判定用 `τ ≤ deadline − t0` | **门控只影响 RT 似然，不影响 OPN**；Wiener 侧需补 `T+200` 处的点质量项（§4.3 阶段 2） |
| **C6** | **求解器必须无梯度**：sklearn `MLPRegressor` 无梯度，不能配 NUTS | HDDM 用切片采样 ✓ 兼容；PyMC 侧只能用 `pm.Potential` + 梯度无关采样器（DEMetropolisZ / SMC），或把网络转 JAX/torch。**原计划"PyMC + NUTS"走不通，Part 5 的写法需改** |
| **C7** | 接 OPN 前先把 `p_outlier` 固定为 **0** | 否则均匀污染分布与遗漏项双重计入（P2-1） |
| **C8** | 在 `Python_HDDM_Nonmatching` 上**挂 Potential** 优于用 PyMC 重写整个 DDM 似然 | 后者要重写 Wiener 似然 + 分层结构，工作量远大于挂一个 `pm.Potential`；且会引入第二套似然实现（违反单一事实来源） |

#### 4.6.3 反推出的接口（三轮实证识别）

| 轮次 | 方法 | 结果 |
|---|---|---|
| 一 | **差值不变性**：由 `F(d, t) = F(d − t)`，找"同时给两槽加同一常数则输出不变"的槽对 | 槽 (3,4) 变化 **0.000161**，次优对 (1,4) 是它的 **130 倍** → `(t, deadline)` 在槽 3、4；**输入未标准化** |

| 三 | **标度搜索**：对 `a` 做变换扫描 | **`a/2`** 使 MAE 从 0.2736 降到 **0.0033**、ρ = **0.9970** |

**最终接口契约**：

```
输入 : (v, a/2, z, t0, deadline)      ← a 是「半分离度」（论文用 ±a 约定，分离度 = 2a）
输出 : exp(raw) = P(omission)          ← 不是 1−exp(raw)（后者 MAE = 0.75）
约束 : batch 固定 = 1，必须逐行推理；输入不标准化
```

⚠️ **`a/2` 暴露了上游仓库的内部不一致**：`runModelDDM.py` 给 ssms 仿真器与 CPN 传的是**同一个** `a1`。
两种可能：① ssms 的 ddm `a` 就是半分离度；② 网络训练用的是论文自己的 `±a` 仿真器（论文 Methods 明写边界在 `±a`）。
**无论哪种，都不能照抄其文档，必须以自家 `sim_utils` 为准做标定**——这正是本轮做的事。

| **P4** | **阶段 1 仍建议以解析 Wiener CDF（或 `sim_utils` 查表）为主口径，论文 OPN 作独立校验器** | 两条独立实现互相对账，符合项目"单一事实来源"纪律；且解析式可求导、便于诊断 |
| **P5** | 阶段 3 直接用 `angle_opn.onnx` / `weibull_opn.onnx` | 省掉自训 LAN+OPN 的全部工作；塌缩边界无解析式，正是这套网络的用武之地 |

#### 4.6.6 对 §4.3 四阶段路线的影响

- **阶段 1**：改用「解析 CDF（主）+ 论文 `ddm_opn.onnx`（校验）」。自家 OPN 的 P0-2 修复（收窄先验重训）**优先级下调**——它现在只是备选。
- **阶段 3**：从"可选"升级为**强烈推荐**。论文已提供 ANGLE / WEIBULL 的现成网络，自己重训的成本与风险都高。
- **P0-1（numba bug）仍然必须修**：只要自家 OPN 还有被使用的可能，这个静默污染源就要堵上。

## 5. 完整落地路线（分步操作手册）

> 目标：把遗漏从"被丢弃/被伪造的缺失值"改造成**第三类反应**，写进似然。
> 数学上只加一项：`logL = Σ_观测试次 log f(rt_i | θ) + Σ_格子 n_遗漏(格子) × log P_遗漏(θ, 格子)`

### 步骤 0：先修四个阻断级错误（不修则后续全白做）

| # | 改什么 | 文件 | 现状 → 目标 |
|---|---|---|---|
| 0.1 | `v` 必须依 `condition` | `Python_HDDM_Nonmatching/step2_hddm_fit.py` | `depends_on={"v":"identity"}` → `{"v":["identity","condition"]}`（§2.2 已证现有设定与数据数学不相容） |
| 0.2 | 消除遗漏伪造 | `Python_HDDM_Nonmatching/step1_prepare_data.py` | 遗漏行由"`rt=deadline` + 恒错方向" → **只标 `omission=1`，不指定方向**（§4.2） |
| 0.3 | `p_outlier` 归零 | 同上 | `0.05` → `0`（否则均匀污染分布与遗漏项双重计入，§4.5.4 P2-1） |
| 0.4 | 剔除 G2-11 后重生成 | `2_Data/Real_Data/` | 87 人口径重跑 `HDDM_Ready*` / `HDDM_Traces*`（现有产物仍含被剔除被试） |

### 步骤 1：实现 `P_遗漏(θ, d)`（三选一，建议 A 为主 + C 校验）

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A（主口径）** | **Wiener 首达时 CDF**：`P_遗漏 = 1 − F_up(D) − F_lo(D)`，`D = deadline − t0`；用 Navarro & Fuss (2009) 的数值实现（`wiener` 包 / `pyddm` / HDDM 内部均可） | 快、可求导、便于诊断 | 需先在自家仿真器上校验实现精度（防第二套事实来源） |
| **B（备选）** | `sim_utils` 网格 + 插值（`(v,a,z,t0,d)` → `p`） | 可逐点对账，无"网络学得对不对"问题 | 需建网格、外推需谨慎 |
| **C（校验器）** | 论文 `ddm_opn.onnx`（接口见 §4.6.3） | 已标定，MAE 0.0104，最省事 | 无梯度、需逐行推理、仓库无 LICENSE |

**建议**：A 做似然主口径，C 做**独立校验器**——两条独立实现互相对账，符合项目"单一事实来源"纪律。

### 步骤 2：把遗漏项挂到 HDDM 上（不要重写 PyMC）

论文自己的写法（`runModelDDM.py`）就是在 `pm.Model` 里挂两个 `Potential`：

```python
with pm.Model() as m:
    v = pm.Uniform("v", -3, 3); a = pm.Uniform("a", 0.3, 3)
    z = pt.constant(0.5); t = pm.Uniform("t", 0.1, 2.0)
    deadline = pt.constant(1.25)
    pm.Potential("choice_rt", lan_logp_op(data_commission, v, a, z, t))   # 观测试次
    pm.Potential("omission",  cpn_logp_op(data_omission, v, a, z, t, deadline))  # 遗漏
```

本项目**不要照抄重写**，而是在 `Python_HDDM_Nonmatching` 的 `pm.Model` 上**加一个 `pm.Potential`**：

```python
# 伪代码骨架：逐格计算遗漏项，再挂到 HDDM 的模型上下文
def omission_potential(model, cell_index, n_omission, deadline, p_om_func):
    """
    cell_index : (n_cell, 3) 每格的 (subject, identity, condition) 索引
    n_omission : (n_cell,)   每格的遗漏试次数
    p_om_func  : (v, a, z, t0, d) -> P(遗漏)，向量化
    """
    import pytensor.tensor as pt, pymc as pm
    with model.model:                      # HDDM 的 pm.Model 上下文
        # 从 HDDM 节点取出逐格参数（v 已是 (subj, identity, condition) 形状）
        v = model.nodes_db["v"].node
        a = model.nodes_db["a"].node
        t0 = model.nodes_db["t"].node
        z = model.nodes_db["z"].node
        p_om = p_om_func(v[cell_index], a[cell_index], z[cell_index],
                         t0[cell_index], deadline)
        pm.Potential("omission_logp", pt.sum(n_omission * pt.log(p_om)))
```

**两个必须确认的点**（建议先做一个 30 分钟 spike）：
1. HDDM 的 `pm.Model` 是否允许事后追加 `Potential`（取决于 HDDM 版本与内部节点注册方式）；
2. 追加后 HDDM 默认的**切片采样器**（无梯度，兼容）混合是否变差。若变差，退回方案 B（查表）并改用 SMC。

### 步骤 3：三条硬约束（写错任一条，结果全废）

| 约束 | 内容 |
|---|---|
| **逐格** | 每 `(被试 × 身份 × 条件)` 各算一个 `p_om`、各乘自己的遗漏数——**不能用被试级单一 `v`**（`Δv ≠ 0`，两格遗漏概率不同） |
| **口径** | `a` = 分离度；`z` 需用 `Φ` 从 `z_trans` 还原（`sim_utils.z_from_trans`）；`t0` 与 `deadline` 同一时间原点，`deadline = T + W` |
| **点质量** | 观测 RT = `max(τ, T+200)`，故 Wiener 侧需补 `T+200` 处的点质量项；**遗漏判定不受门控影响**，OPN 侧无需改 |

### 步骤 4：验收——三臂对比必须同时报告

| 臂 | 遗漏处理 | 说明 |
|---|---|---|
| **Drop** | 删除遗漏行 | 现行常见做法，Leng et al. 证明有偏 |
| **Censor** | `rt=deadline` + 固定方向 | 项目现行做法，**已证有误导**（§4.2） |
| **Omission-aware** | 遗漏进似然（本方案） | 目标方案 |

四项判据同时满足才算通过：① 逐条件遗漏率对齐（阶段 0 已达 MAE 0.072，不应变差）② responded 正确率对齐（0.047 不应变差）③ RT 分位对齐 ④ 报告三臂的参数差异。

### 步骤 5：再考虑是否升级到塌缩边界（阶段 3）

恒定边界跑通后，若发现遗漏缺口仍集中于某些条件（如 g3），再评估 ANGLE / WEIBULL：
- 论文已提供 `angle_opn.onnx` / `weibull_opn.onnx`，省掉自训 LAN+OPN 的全部工作；
- ⚠️ 但这两个网络**尚未标定**：只确认了输入维度（6 / 7 维），精度与参数顺序需按 §4.6.3 同样的三轮流程重做一遍。
