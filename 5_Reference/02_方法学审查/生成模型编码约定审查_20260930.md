## 0. 一句话结论

`S2 gen_data_jh.ipynb` 的问题不在参数，而在它**没有声明自己的编码约定**：它实际是「响应编码 + 只跑匹配条件 + 起点锁死在 a/2」三者叠加。这恰好把项目最想回答的问题抹掉了——因为 **SPE 的机制解释有两套（证据优势 vs 匹配键偏向），而它们在"只跑匹配试次"的数据上给出完全相同的预测**。用一手数据核查后确认：**87 名被试的自我优势同时存在于辨别力 d′ 和判断标准 c 两条通道上**（合并口径 Δd′ = +0.41、Δc = −0.24），所以这不是"锦上添花"，而是必须补齐的设计维度。

## 1. 生成模型当前的三个隐含假设

| 代码里的量 | 实际承担的角色 | 是否在代码/文档中声明 |
|---|---|---|
| 证据在 `0` 与 `a` 之间累积，`response = 1 / 2` | 两个边界 = **两个按键**（响应编码） | ❌ 未声明 |
| `evidence = a / 2` | 起点 **z ≡ a/2**，即"无反应偏向" | ❌ 未声明为假设 |
| `conditions = {0:'stranger', 1:'self'}` | 只有"身份"因子，**没有刺激因子** | ⚠️ 仅在 `Aim.md` 外部说明"只模拟 Matching" |
| `compute_v(T, P, condition)` | 身份只进 `v`，且为**乘性** `×(1+α)` | ❌ 未声明 |
| `while trial_count < ...` + 丢弃重采样 | 无遗漏机制，只有"删掉慢试次再凑数" | ❌ 未声明 |

**关键后果**：它生成的世界里**没有刺激，只有按键**。正确与否在生成器内部是未定义的——只有当外部补上「上界 = 该被试的匹配键」且「全部是匹配试次」两个假设时，`response=1` 才等价于"正确"。这两个假设都没写进代码，也没写进论文。

## 2. 问题：`z ≡ a/2` + 只跑匹配条件，丢掉了哪一半

### 2.1 两套机制解释

- **H1 证据优势**：自相关刺激的证据积累更高效 → 漂移率 `v` 更高 → 又快又准。
- **H2 匹配键偏向**：自我让"匹配"这个反应更占先 → 起点 `z` 偏向匹配键 → 匹配试次上又快又准。

### 2.2 为什么"只跑匹配条件"分不开它们

匹配试次里「匹配键 = 正确键」，`v` 和 `z` 指向同一个边界，两者预测完全相同。它们只在**不匹配试次**上分道扬镳：同一份"偏向匹配键"的 `z`，在不匹配试次里偏向的是**错误**那一侧，因此表现为**反向**的效应。

| | 匹配试次 | 不匹配试次 |
|---|---|---|
| 本生成器（z 固定 a/2） | 唯一覆盖的格子 | **完全未生成** |
| H1 证据优势（Δv > 0） | 自我更快更准 | 自我更快更准（同号） |
| H2 匹配键偏向（Δz > 0） | 自我更快更准 | **自我更慢更差（反号）** |

**所以：不匹配试次不是"额外的数据"，它是把 `v` 与 `z` 分开的钥匙。** 不是标准 DDM 顾不全，是设计被砍掉了一半。

## 3. 一手数据核查（87 名被试，45,240 个正式试次）

复现：`python _scratch/check_nonmatch_quality.py`（只读，不改动任何数据）

### 3.1 入库质量

- **88 名被试中 87 名的 `CorrectKey`** 与「按被试编号取模」推出的理论映射**完全一致**（0 处偏差）。
- **唯一异常 `EXP_data_group2_11.csv`**（G2 · 被试 11 · mod 3）：理论应为 SAME 模式、实为 ALT 模式，**100% 反转**（1320 个正式试次全部错位）。与 `1_Code/Experiment/exp_matlab/test/刺激呈现期按键无法记录_原因排查与结论.md` 早前的排查记录一致。
  **→ 2026-09-30 决定：剔除该被试**（原因：中途实验卡死、重新进入后按键映射记录错误）。文件移至 `2_Data/Real_Data/Excluded/`，说明见其 `README.md`。**本节及以下所有数字均为剔除后的 87 人口径。**
- `Correct` 列与 `(Response == CorrectKey)` **0 处冲突**；`Response` 取值只有 `f` / `j` / 缺失，无脏值。
- 四格各 11,310 试次，**完全平衡**，不匹配列可放心用于建模。

### 3.2 四格描述统计（逐被试均值，仅正式试次）

| 格子 | 正确率 | 平均 RT (s) | 遗漏率 |
|---|---|---|---|
| 匹配 · 自我 | 81.07% | 0.532 | 27.55% |
| 匹配 · 陌生人 | 66.83% | 0.559 | 32.18% |
| 不匹配 · 自我 | 61.89% | 0.562 | 31.92% |
| 不匹配 · 陌生人 | 63.33% | 0.564 | 32.69% |

自我优势**集中在匹配列**（ACC +14.2 pt、RT −27 ms），到不匹配列几乎消失（ACC −1.4 pt、RT −2 ms）。

### 3.3 信号检测论分解（合并口径）

信号 = 按「匹配键」；`H = P(按匹配键 | 匹配试次)`，`FA = P(按匹配键 | 不匹配试次)`。
`d′ = z(H) − z(FA)`（辨别力）；`c = −0.5·(z(H)+z(FA))`（**负值 = 偏向匹配键**）。比例用 log-linear 校正。

| 口径 | 身份 | H | FA | d′ | c |
|---|---|---|---|---|---|
| A 只算有反应 | 自我 | 0.834 | 0.318 | **1.443** | **−0.248** |
| A 只算有反应 | 陌生人 | 0.701 | 0.306 | 1.034 | −0.009 |
| A **差值** | 自我 − 陌生人 | — | — | **+0.410** | **−0.239** |
| B 遗漏算没按匹配键 | 自我 | 0.604 | 0.216 | 1.048 | +0.260 |
| B 遗漏算没按匹配键 | 陌生人 | 0.475 | 0.206 | 0.758 | +0.441 |
| B **差值** | 自我 − 陌生人 | — | — | **+0.290** | **−0.182** |

**结论：自我优势同时出现在 `d′` 与 `c` 两条通道上——既有"证据更准"，也有"更偏向匹配键"。** 后一半是 `z ≡ a/2` 无论如何都表达不出来的。

### 3.4 必须随行报告的三个限定

1. 这是**描述性 SDT**，不是 DDM 拟合；`d′`/`c` 把所有潜参数（v、a、z、t0）混在一起，只能作为"存在两个成分"的初筛，不能替代刺激编码模型的参数估计。
2. **遗漏率约 30%，且自我低于陌生人**（匹配列 27.6% vs 32.2%）。口径 A 与 B 的差异完全来自这一点。因此遗漏必须作为**第三类反应**显式建模（对应 `07_文献与技术路线/Omission_*` 那条线），不能当噪声丢掉。
3. 逐被试再平均的 `d′`（口径 A：自我 1.462 / 陌生人 0.953）被天花板效应放大，**不要单独引用**；以合并口径为准。

## 4. 修复路线

> ⚠️ **续篇**：具体的参数化落地方案、以及对**既有 `1_Code/Python_HDDM_Nonmatching/` 流程模型设定错误**的证明与修正，
> 见 [`路线B模型规格与遗漏建模路线_20260930.md`](路线B模型规格与遗漏建模路线_20260930.md)。
> 一句话结论：现有流程用 `depends_on={"v": "identity"}`（匹配与不匹配共用同一个 v），
> 该设定在数学上要求 `P(正确|匹配) + P(正确|不匹配) ≡ 1`，而实测为 **1.458**，故必须修正。

三条路线，**共同前提都是"把编码写成显式声明"**，区别在覆盖范围。

### 路线 A｜最小改动：只声明，不扩范围

- 输出增加 `correct` 列，明确「上界 = 该被试的匹配键」（真实数据里匹配键按被试轮换 `['f','j','j','f']`，见 `1_Code/Python_for_Check/Visualization/app_server.py`）。
- 明确写出 `z = a/2` 是**假设**而非估计，并声明"本生成器不建模反应偏向"。
- 真实数据重编码为正确性编码，只用手上的 260 个匹配试次。
- **代价**：`Δc = −0.23` 这个成分被结构性忽略；每人 260 个不匹配试次闲置。

### 路线 B｜全 2×2 + 刺激编码（推荐）

采用 HDDM 的 **stimulus coding**：**`v` 与 `a` 按「正确性」编码，`z` 按「按键」编码**。

- 设上界 =「匹配」键、下界 =「不匹配」键；`z > a/2` 表示偏向匹配键。
- 四格的漂移方向：匹配·按匹配键（正确）向**上**；匹配·按不匹配键（错误）向**下**；不匹配·按不匹配键（正确）向**下**；不匹配·按匹配键（错误）向**上**。
- **起点 `z` 恒定偏向匹配键，与刺激条件无关**——这正是同一份偏向在两列上反向作用的来源。
- 于是 `Δv`（证据优势）与 `Δz`（匹配键偏向）在生成器里**天生可分**，且输出同时带 ACC 与 RT，可对齐真实数据的正确率、`d′`、`c`、CRF 与滑动窗口。
- **成本**：需扩展生成器 + 用刺激编码重拟合真实 HDDM。但**数据已有**（每人 260 个不匹配试次），且仓库已有配套资产（`1_Code/Python_for_Check/ddm_stim_coding/`、`1_Code/Python_HDDM_Stim-Coding_Simulation/`）。
- **建议的初始参数化**：`z = z₀ + Δz·I_self`（2 个参数），因为 `Δz` 正是理论上要检验的量。

### 路线 C｜响应编码拆四格

保留按键界，让 `v` 分四格（自我/陌生人 × 匹配/不匹配），不设 `z`。实现最省事，但 `a` 失去"速度—准确权衡"的解释，且四格漂移彼此高相关。

## 5. 与"整体思路"相关的三处附带问题（与参数无关）

1. **循环论证风险**。生成器里的 Sigmoid 就是假设本身（`P→v`、`M→a`）。用同一套函数生成"数据"、再用它检验"模型能否恢复设计效应"，只证明仿真器自洽。建议给每个 notebook 显式声明角色：是「合成数据 / 设计敏感性工具」（真值须来自别处），还是「校准过的前向模型」（参数由真实数据反推）。`Py/Generate_Data_v2.5_tuning.py` 的 `TARGET_SPE` 逐组网格搜索是该问题的极端形态。
2. **遗漏被"丢弃 + 重采样"替代，改变了分布**。deadline 处截断再重采样凑够试次数，产出的是**截断重条件化**数据而非**删失**数据：逐条件 RT 被系统性压低，"每人 130 试"也不是设计的试次数。应把 `omitted` 当结果输出（RT 置空、保留真实试次数），让遗漏率成为模型输出。
3. **身份效应只被允许进入 `v`**。SPE 可能落在 Δv / Δz / Δa / Δt0 任一通道，现在同时锁死 Δz、Δa、Δt0。最小改法：身份项由**乘性** `×(1+α)` 改为**加性** `+Δ·I`，否则 `α` 与 `v_P` 在乘法里混叠（跨条件反推的 `α₁−α₂` 从 −0.16 飘到 +0.69，函数形式与数据不相容，见 `生成模型与GP探索_代码审计_20260916.md` §2.1）。
