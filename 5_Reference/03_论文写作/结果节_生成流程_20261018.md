## 2. 结果章的节次顺序（建议）

1. **被试与数据质量**：N、各组人数、练习段是否走通、剔除了几场（`intake` 的 `EXCLUDE`）、为什么。
2. **行为层**：正确率与 RT 中位随 P 的变化（`fig1`）。这一段先给事实、不给模型解释。
3. **模型比较**：M-T1（两阶段）vs M-T3（单阶段）的 Δelpd + SE + Pareto k 诊断是否可用。
4. **参数估计**：组层参数（`d_ref`、`beta_T`、`beta_S`、`beta_ST`、`a_ref`、`delta_a`、`t0`、`rho`）与理论预期对照（`fig2`）。
5. **假设检验的落点**：P 效应（`beta_P`）在行为层与参数层分别是什么结论；两者不一致时怎么写。

## 3. 参数表的口径（必须写清，否则读者无法复现）

- 组层点估计 = 超参数均值反变换到自然尺度：`v = lo + (hi − lo)·expit(mu)`
  （`mu` 是无约束坐标里的超参数均值，`lo/hi` 见 `mapping.PARAM_BOUNDS` 与
  `twophase.MASK_RHO_BOUNDS`）。
- `fig2` 里的区间是**被试间 SEM**（被试层众数的 SD / √n），**不是**后验 SD、
  也不是拉普拉斯协方差。表里若报 95% 区间，必须写明是「被试间」还是「后验」。
- `rho` 是掩蔽期漂移比：`rho = 1` 退化为单阶段；`rho < 1` 表示掩蔽期漂移下降。

## 5. 写论文时的三条硬纪律

1. **合成数据的任何数字都不进正文**：目录里有 `synth_truth.json` ⇒ 所有产物只证明流水线可跑通。
   本仓 `2_Data/Real_Data/_SYNTHETIC_DEMO_v1/` 就是这种数据。
2. **`k_diag_ok = false` 时不许写「模型比较支持 M-T1」**：只能写「流程验证通过，
   正式比较需 `n_draws ≥ 25` 的重跑结果」。
3. **行为层与参数层分开陈述**：行为层 `f`/η² 不蕴含参数可估（`beta_ST` 反例，
   见主计划 D97 与 `1_Code/DDM_Core/README.md` §8.68）。

## 6. 数据到位后的操作顺序

1. 跑 `run_pipeline.py <批次> --profile formal`（后台，数十小时）。
2. 读 `pipeline_report.md` → 确认四步退出码全 0。
3. 读 `_pipeline/results_skeleton.md` → 把三张表 + 三张图搬进 `_v3_正文.md` 的结果章。
4. 补 `【待写】` 的论述；每处结论都要能指回某个判据或某张图。
5. 更新 `5_Reference/08_工作流/工作流_主计划.md` 的 §2/§3 Stage 8 状态与进度表。
