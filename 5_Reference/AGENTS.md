## 一、这个文件夹是什么

`5_Reference/` 存放**与代码和数据分离的文档层**：选题方案、方法学审查、论文写作、格式模板、交付件、进展汇报、文献与技术路线、思路历程。

**它不存放**：代码（→ `1_Code/`）、数据（→ `2_Data/`）、图表产物（→ `3_Figures/`）。

## 四、编辑文档时的规范

1. 新建/大改文档，头部必须有四行：`日期` / `状态` / `依据` / `权威性`。
   状态取值：`✅现行`、`⚠️部分过时`、`🗄️仅历史`、`❌已被推翻`。
2. **归档目录不要改**：`_历史版本/`、`_旧稿/`、`_抽取文本/`、`99_归档/` 里的文件保留原样（含失效引用），这样才看得出当时状态。
3. 新增/移动文档后，回到 `README.md` §三 更新清单。
4. 发现两份文档结论冲突时：**先回到一手证据**（实验源码、原始 CSV、重新计算），再决定谁对，最后更新 `README.md` §五。
5. 文件命名：`主题_版本或日期.扩展名`，日期用 `YYYYMMDD`；`_` 前缀表示派生/工作文件。
6. 中文注释与中文文档；交付类 docx 只有一种命名格式：`毕业论文_蔡振辛_初稿v{主}.{次}_图版_{YYYYMMDD}.docx`。

## 五、代码规范（写 `1_Code/` 下的脚本时适用）

- 注释用中文；变量名用英文；路径统一用 `pathlib.Path`。
- 导入顺序：`numpy` / `pandas` / `matplotlib` → `sklearn` → `scipy`。
- 中文输出的脚本，开头加 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`，避免 Windows 控制台 GBK 报错。
- **仿真器只有一个事实来源**：`1_Code/Python_for_Check/TenRules_Revision_20260912/sim_utils.py`。不要另起一套 DDM 仿真实现。

## 六、容易踩的坑（历史教训）

| 坑 | 表现 | 防法 |
|---|---|---|
| 拿文档当事实 | deadline 口径被一份审计报告"统一"错，且该报告自相矛盾 | 回一手证据 |
