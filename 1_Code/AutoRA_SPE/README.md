## 1. 一句话定位

把 GP 从「生成模型的残差修正层」（已被本人数据否证：LOCV 1.232 > 纯 Sigmoid 1.135，模型恢复 0/40）
**换槽**为「设计空间上的代理模型 + 采集信号」，并用 AutoRA 的
`Experimentalist × Experiment Runner × Theorist` 闭环把它跑起来。

**GP 的评判标准随之改变**：不再是「预测准不准」，而是「**用几个设计点达到目标精度**」。

## 2. AutoRA 架构映射

| AutoRA 组件 | 本项目实现 | 文件 |
|---|---|---|
| **Experimentalist**（采集函数） | GP 代理 (P,T,W)→目标 + EI/不确定性采集 | Phase 2 |
| **Experiment Runner**（合成被试） | 虚拟被试前向仿真 | `spe_runner.py` |
| **Theorist**（估计/模型比较） | 快速估计器（内环）/ HDDM（最终点验证） | Phase 1 |
| **Objective**（冻结、只读、哈希锁定） | 参数恢复精度 + 模型判别信息 + 约束惩罚 | Phase 1 |
| **State / Cycle** | AutoRA 状态机制或自研循环 | Phase 2 |

### Token 结构（重要）

**闭环本身消耗 0 token。** Experimentalist（sklearn）、Runner（numpy）、Theorist（docker/本地）、
Objective（python）全部本地运行，无 LLM 调用。Token 只花在两处：
① 开发/调试这套代码（一次性）；② 你让 LLM 解读结果或写论文。
**不要用 LLM 做参数搜索——那是 GP 的职责。**

## 3. ⚠️ 权威时序口径：`deadline = T + W`（不是 `T + 200 + W`）

### 证据一：实验源码直接写明

`1_Code/Experiment/exp_matlab/Exp_Design_Formal_v2.m`：

```
L20   %   = P8/T100ms/W1100ms/M0（与组5唯一差别是掩蔽，deadline 同为 T+W=1.2s）
L479  maskDuration = 0.2;
L506  maskOffsetTime = maskFlipTime + maskDuration;
L513  % 4. 显示空白屏，等待键盘反应，持续反应窗口 W - maskDuration
L519  %   deadline 与 v1 完全一致（responseFlipTime + W - maskDuration）；
L963  while GetSecs() - responseFlipTime < W - maskDuration
```

反应窗口在 `刺激onset + T + 200 ms` **打开**，持续 `W − 200 ms`，
因此在 `刺激onset + T + W` **关闭**。

### 证据二：实测 RT 独立确证

| group | T | W | 最大反应 RT | T+W | 反应窗口时长 W−200 | 观测遗漏 |
|---|---|---|---|---|---|---|
| 1 | 30 | 300 | 332.4 | **330** | 100 | .723 |
| 2 | 30 | 600 | 632.8 | **630** | 400 | .524 |
| 3 | 30 | 600 | 635.4 | **630** | 400 | .386 |
| 4 | 80 | 600 | 683.6 | **680** | 400 | .384 |
| 5 | 100 | 1100 | 1194.2 | **1200** | 900 | .109 |
| 6 | 500 | 1500 | 1975.2 | **2000** | 1300 | .056 |
| 7 | 30 | 800 | 884.3 | 830 | 600 | .143 |
| 8 | 80 | 800 | 884.3 | **880** | 600 | .147 |

- 最大反应 RT ≈ **T + W + 2 ms**（7/8 组；g7 为已知异常）。
- **遗漏率与"窗口时长 W−200"精确对应**：g3/g4 同为 400 ms → 遗漏 .386/.384；
  g7/g8 同为 600 ms → 遗漏 .143/.147。
- 若 deadline 真是 `T+200+W`，则 8 组的最大反应 RT 会一致地比 deadline **低 145–225 ms**，
  这在 8 个独立条件上同时成立是极不可能的。

### 由此更正的两处错误

| 来源 | 原说法 | 判定 |
|---|---|---|
| 本文件初版 / `spe_design_model.py` 初版 | `deadline = T + 200 + W` | ❌ **错**（多加一个掩蔽时长） |
| `项目脉络梳理与行动清单_20260916.md` §5 P0-1 | 「统一为 `T/1000 + 0.2 + W/1000`」 | ❌ **错**，且该段自相矛盾——同时把 `sim_utils.py` 的 `(T+W)/1000` 标为 ✅ |
| `sim_utils.py` / `automation/core/generative_model.py` | `T + W` | ✅ **对** |

**好消息：论文配置 C 的全部数字由 `sim_utils.py`（用的是正确的 `T+W`）产生，因此不受影响。**
错的只是本次新建的模块和审计报告的建议。

### 另一个必须澄清的语义

设计表里的 **`W` 不是"反应窗口时长"，而是"反应窗口关闭时刻"（自刺激起点计）**。
真正的可反应时长 = `W − 200 ms`（`window_duration_ms()`）。

| group | 有效窗口时长 | T |
|---|---|---|
| 1 | 100 | 30 |
| 2,3,4 | 400 | 30/30/80 |
| 7,8 | 600 | 30/80 |
| 5 | 900 | 100 |
| 6 | 1300 | 500 |

## 4. Phase 0 验收结果（2026-09-17）

运行：`python check_simulator.py`（D1–D7）+ `python diag_observed_rt.py`（观测分布诊断）
数据：`2_Data/Generate_Data/AutoRA_SPE/*.csv`

### 通过

| 检查 | 结果 |
|---|---|
| **D2 RT 下界** | 8 组 `min RT − T` = 202.8–203.1 ms，回归 **slope = 1.000, intercept = 203.0** |
| **窗口门控** | 最小 RT 误差 **115.8 ms → 3.0 ms**；被试内一致性检验 0/88 违反 |
| **D5 deadline** | 权威口径 `T+W`；`T+W−t0` 灾难性（3 个条件遗漏率仿真成 100%） |
| **D1 设计结构** | 见 §5（更正审计报告） |
| **D3 截尾伪影** | r(遗漏率, v_base) = **−0.747**；两对 W 配对同向 +2.79 / +2.37 |

### 遗漏率缺口在修对 deadline 后基本闭合

| 变体 | 遗漏率 MAE | 正确率 MAE | 最小 RT MAE |
|---|---|---|---|
| 历史（逐条件 t，无门控，**错误 deadline**） | 0.126 | 0.111 | 3.0 ms |
| 修正（t0=0.2 + 门控 + **错误 deadline**） | 0.122 | 0.068 | 3.0 ms |
| **修正（t0=0.2 + 门控 + 被试间变异 + 权威 deadline）** | **0.072** | **0.047** | **3.0 ms** |

逐条件（修正+变异 vs 观测）：

| group | 观测遗漏 | 仿真遗漏 | 观测正确率 | 仿真正确率 |
|---|---|---|---|---|
| 3 | .386 | **.165** ← 唯一明显失配 | .325 | .262 |
| 4 | .384 | .359 | .451 | .427 |
| 5 | .109 | .067 | .683 | .693 |
| 6 | .056 | .005 | .887 | .950 |
| 7 | .143 | .091 | .683 | .674 |
| 8 | .147 | .186 | .694 | .807 |

**→ 6 个条件中 5 个的遗漏率对上了（误差 ≤ .05）。**

### 唯一未闭合的 g3，定位到估计问题而非机制问题

g3（P120/T30/W600）观测遗漏 .386、仿真 .165。原因是它在配置 C 中的 v 估计极端且几乎未识别：

```
v_stranger: [-7.24, +3.44]     v_self: [-7.73, +3.31]
```

即 g3 的 v 后验跨度为 11 个参数单位——**该条件的 v 实际上不可识别**。
而 g4 与 g3 的有效窗口时长完全相同（400 ms）、观测遗漏也几乎相同（.384 vs .386），
仿真却能对上（.359）。**两者唯一差别是 g3 的 v 估计值失真。**

→ 结论：**这不是"缺少 lapse 机制"，而是"g3 的 v 不可识别"。**
这正是设计优化要解决的问题（哪些设计点能让 v 可识别），而不是往生成器里塞机制。

### 三次尝试的完整记录（lapse 假设的否证过程）

| # | 尝试 | 结果 |
|---|---|---|
| 1 | 被试间参数变异 | 正确率误差 0.111→0.068 ✅；遗漏率几乎不变 0.126→0.122 ❌ |
| 2 | 跨试次漂移变异 **sv** | 遗漏率 MAE 0.121→0.115，**假设否证**（D6） |
| 3 | 机制化 lapse（v←0） | 遗漏率 MAE 0.076→0.043 但 responded 正确率 MAE **变差** 0.096→0.146，**形式否证**（D7） |
| 4 | **更正 deadline 口径** | **遗漏率 MAE 0.121→0.072，正确率 0.068→0.047，同时改善** ✅✅ |

→ **遗漏缺口的真正原因是 deadline 口径写错，而不是缺少 lapse 机制。**
  `lapse_prob` 保持 **0.0**；审计报告 P1-11「去掉 lapse，让遗漏自然涌现」**成立**。

### 已修复的 5 处（对应审计 P0）

1. `deadline = T + W`（权威口径，见 §3）
2. **反应窗口门控**（新增）：决策自刺激起始，按键只在 `[T+200, T+W]` 内记录
3. 身份项**乘性 → 加性**（`v_self = v_base ± ΔI/2`，ΔI ≡ SPE_v 可直接解释）
4. `k_min/k_max` → `k_at_low_P/k_at_high_P`（原命名与语义相反）
5. 保持无 lapse（经 §4 的三次否证后确认正确）

## 5. 两条对既有文档的更正（除 deadline 外）

### 5.1 审计报告说错了：W 是覆盖最好的维度

`项目脉络梳理与行动清单_20260916.md` §6 称「T 与 W 在所有条件里同向变化，W 的独立效应不可识别」。
**实际存在三对固定 (P,T) 只变 W 的最小配对**：

| P | T | W 对比 | 有效窗口时长对比 | 组 |
|---|---|---|---|---|
| 0 | 30 | 300 → 600 | 100 → 400 | g1 → g2 |
| 120 | 30 | 600 → 800 | 400 → 600 | g3 → g7 |
| 120 | 80 | 600 → 800 | 400 → 600 | g4 → g8 |

W 有 5 个水平、有效窗口时长也有 5 个水平（100/400/600/900/1300）；
**T 只有 4 个水平且 T=500 仅一组**。
→ 审计报告建议补的 **D5「固定 T=30 压 W」是多余的**（g3 vs g7 已是该对照）。
**真正缺的是 T 的中间水平。**

### 5.2 新程序有 9 个条件，且含一个 M（掩蔽）因子

`Exp_Design_Formal_v2.m` L14-25：组 1–6、8–9 为有掩蔽条件，**组 7 为无掩蔽条件**
（= P8/T100/W1100 去掉掩蔽）。且 **v2 的组编号与 `HDDM_Ready` 的组编号不一致**
（v2 组8 = P120/T30/W800，而 `HDDM_Ready` group7 = P120/T30/W800）。
→ 后续合并新数据时必须先对齐编号，否则会串组。
