## 超限原因：Psychtoolbox 系统开销

**RT 超限不是实验逻辑错误或数据损坏，而是 Psychtoolbox 每试次必须承受的 ~50ms 系统开销**。

### 试次时间线分析

```
stimulusFlipTime (t₀)         ← 刺激出现，RT 计时起点
    │
    ├─ 刺激可见 T 秒（无按键检测）
    │
    ├─ checkEscape()           ~0.5ms
    ├─ imread() 加载掩蔽图片    ~5-15ms   ← 每试次随机选掩蔽图，未预缓存
    ├─ MakeTexture()           ~2-5ms
    ├─ Screen('Flip') 等待vsync ≤16.7ms   ← 第1帧延迟（60Hz）
    │
maskFlipTime                   ← 掩蔽出现
    │
    ├─ 掩蔽可见 200ms（无按键检测）
    │
    ├─ checkEscape()           ~0.5ms
    ├─ Screen('Flip') 等待vsync ≤16.7ms   ← 第2帧延迟（60Hz）
    │
responseFlipTime               ← 反应窗口开始
    │
    ├─ 反应窗口 W - 200ms（含 KbCheck）
    │
    └─ 窗口关闭时刻 ≈ t₀ + T + W + 系统开销
```

### 系统开销分解

| 来源 | 典型延迟 | 说明 |
|------|---------|------|
| 掩蔽图片加载 (`imread` + `MakeTexture`) | 10-20ms | 每试次动态加载，非预加载资源 |
| 第 1 次 `Screen('Flip')` vsync 等待 | ≤16.7ms | 刺激结束到掩蔽出现，必须等下一个刷新周期（60Hz ≈ 16.7ms/帧） |
| 第 2 次 `Screen('Flip')` vsync 等待 | ≤16.7ms | 掩蔽结束到空白屏，再等一个刷新周期 |
| USB 键盘轮询率（125Hz 默认） | ≤8ms | 按键到 `KbCheck` 检测存在硬件滞后 |
| OS / MATLAB 调度抖动 | 5-10ms | 进程抢占、中断处理、内存管理 |
| **合计** | **≈50-55ms** | |

### 各组超限幅度与系统开销的对应

- **D3b (+56.6ms)**：T+W=830ms 最短的反应窗口组，系统开销占比最显著，56.6ms ≈ 3.4 帧 + 键盘延迟
- **D2/D3a (+12-16ms)**：约 1 帧延迟，属于典型情况
- **D1/D4a/D4b (+3-7ms)**：远小于 1 帧，几乎在理论范围内
- **D5/D6 (0ms)**：T+W 足够长（1200-2000ms），所有被试均在截止前完成反应

---

## 处理建议

1. **分析中使用 T + W + 60ms 作为 RT 上限**：将 0-60ms 超限视为正常系统开销，不作为无效数据剔除
2. **D3b 的 282 次超限（4.52%）**：虽超限次数较多，但均为系统开销级别（≤56.6ms），可保留
3. **如需更精确的 RT 上限**：可考虑升级为 Psychtoolbox `KbQueue`（事件驱动按键检测），并预加载掩蔽图片纹理以消除加载开销
